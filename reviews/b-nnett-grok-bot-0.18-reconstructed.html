b-nnett/grok-bot-0.18-reconstructed is an unofficial TypeScript reconstruction of the publicly shipped Grok Bot 0.18.0 macOS app. The repository attempts to reverse engineer the desktop application's internals and provide readable implementations of its Electron, host, coordinator, local-execution, protocol, and renderer boundaries. The specific problem it solves is understanding how the original app was put together. The author expanded the reconstruction with an inference router for Cursor, Claude Code, Codex, and OpenRouter, plus Grok Bot plugin and MCP tools across those providers, local usage tracking, an optional local Docker sandbox, and a reconstructed settings surface. The codebase is large at 364,798 lines across 2,111 files.

Getting it running took three attempts. The documented usage worked, but only after troubleshooting the TypeScript module resolution. The first obstacle is that the project ships as raw TypeScript source with no straightforward entry point or prebuilt artifacts. To run anything, I had to locate the specific source file and transpile it manually. The command that finally worked used npx tsc with the modern moduleResolution bundler flag, targeting es2022 with esModuleInterop and skipLibCheck enabled. I pointed the compiler at source/packages/agent-transcript/context-stripping.ts and output to a temporary directory. The transpile succeeded and produced /tmp/rr/transpiled/context-stripping.js. No missing system libraries or external dependencies beyond the standard Node and TypeScript toolchain were needed. The npm test suite reports exit 1, so the built-in tests do not pass.

When I ran the transpiled code, I tested the stripContextTags function from the agent-transcript package. The input string was "Please <context>remember this context</context> when answering." The real output was identical to the input: "Please <context>remember this context</context> when answering." This means the function did not strip the context tags. The expected behavior based on the function name and the module's purpose in the agent transcript pipeline would be to remove those tags and return "Please when answering." or similar. The function as currently implemented appears to return the input unmodified, which suggests the reconstruction is incomplete or the tag-stripping logic has a bug or placeholder implementation that does not handle this case.

The architecture is layered across several boundaries. The electron-main/main.ts file defines the main process interface, including MainWebContents and MainBrowserWindow interfaces that abstract Electron's window and web contents APIs. It handles application menu installation, DevTools gating, window focus forwarding, and state persistence. The node-agent-coordinator/main.ts file is the coordinator layer, importing scheduling policies, gateway clients, WebAuthn providers, and the inference router. It sets up the control port client, renderer port server, and local exec daemon supervisor. The packages/agent/index.ts file is the agent core, handling background summarization, interaction listeners, privacy classification, and conversation state. It imports action handlers for user messages, resume operations, subscription notifications, goal continuation, and summarization. The packages/agent-transcript/index.ts module manages conversation transcripts, defining interfaces for TranscriptMessage, TranscriptState, and TranscriptBlobStore. It handles serialization of Uint8Array blobs, oversized transcript thresholds at 5 million bytes, and turn-ended markers for success, error, and aborted states.

The code quality is mixed. The TypeScript is heavily typed with readonly interfaces and explicit type definitions throughout, which suggests careful design work. The import structure in packages/agent/index.ts is dense, pulling from agent-summarization, agent-core, redaction, context, metrics, and redacted-protos packages. The redaction layer with PrivacyCapability and PrivacyMode classes indicates the original app had sensitive data handling. The presence of an inference router that normalizes AnysphereAgentConfig and routes across multiple providers is a practical extension beyond the reconstruction. The main rough edge is that tests are completely absent. The metadata shows 0 test files. CI is enabled, but with no tests and npm test exiting 1, the CI is not providing meaningful coverage. The license is unknown, which is a concern for anyone considering production use.

The verdict is that this repository is for developers who want to study how Grok Bot's desktop architecture works, not for anyone who needs a working tool today. The inference router and MCP plugin extensions are interesting if you are building a multi-provider agent setup, but you will need to read the code carefully because the test suite does not exist to catch regressions. The stripContextTags bug I encountered is a concrete example of the kind of gap you will find: the function exists, is typed, is imported by the transcript module, but does not actually strip tags. If you are researching Electron agent architectures or want a reference for how to structure a multi-provider inference router, the code is worth reading. If you need a reliable agent framework, the missing tests and incomplete implementations mean you will be debugging and fixing things yourself. The 3,457 stars suggest genuine interest, but the unknown license and zero test coverage mean you should treat this as a research artifact, not a dependency.

cd /tmp/rr/b-nnett_grok-bot-0.18-reconstructed

  "$(find . -name "context-stripping.ts" -not -path "*/node_modules/*" 2>/dev/null | head -1)" \
  --outDir /tmp/rr/transpiled || true

# Check what was produced
find /tmp/rr/transpiled -name "context-stripping.js" 2>/dev/null
