I cloned b-nnett/grok-bot-0.18-reconstructed today to see what a source-oriented reconstruction of Grok Bot 0.18.0 actually looks like. The repo sits at 3181 stars and is rising, which makes sense given the current appetite for understanding how shipped AI desktop apps work. This is an unofficial TypeScript reconstruction of the macOS Electron app, not a reverse-engineered binary or a scraped UI. Someone read the shipped app carefully and wrote readable TypeScript implementations of its Electron, host, coordinator, local-execution, protocol, and renderer boundaries, then added a deterministic toolchain for turning those sources back into a working macOS application. The README also lists practical extensions: an inference router for Cursor, Claude Code, Codex, and OpenRouter, plugin and MCP tools across routed providers, local usage tracking, an optional local Docker sandbox, and a reconstructed settings surface. The scale is real: 364,798 lines of TypeScript across 2,111 files.

Getting it running was straightforward in our case. The documented usage worked as-is on the first attempt. I ran a shell script that inspected the package layout, checked for tsx and tsc availability, and attempted a minimal import of the core transcript module. The repository structure is clean. Running find for TypeScript files immediately surfaced the real source tree: frontend/vite.config.ts, frontend/src/recovered/contracts/surface-notice.ts, frontend/src/recovered/contracts/rpc-edge.ts, frontend/src/recovered/contracts/desktop-bridge.ts, frontend/src/recovered/contracts/main-rpc.ts, frontend/src/recovered/catalog.ts, and a deep tree of recovered features under frontend/src/recovered/features covering window-chrome, access, settings, and onboarding. The package.json declares the name grok-bot-0.18-reconstructed at version 0.18.0-reconstructed.1, private true, type module. No missing system libraries, no dependency hell, no patches needed. The test suite is another matter: npm test exits with code 1, and the repo reports zero test files, so that failure is structural rather than a code regression.

What actually happened when I ran it confirmed the repo is a reconstruction you can read and import, not a testable application. I wrote a minimal script that imported stripContextTags from source/packages/agent-transcript/index.ts and fed it the string "Here is a message <context>some context data</context> with tags". The directory listing confirmed the module exists alongside context-stripping.ts, paths.ts, and trace-format.ts. The import path resolution worked and tsx was available, which means the core modules are genuinely importable TypeScript, not stubs. But with zero test files and npm test exiting 1, there is no verification layer. The output tells you the code is structurally sound at the module level but unverified by any suite.

The architecture is substantial and the source confirms real engineering. The agent-transcript package handles conversation persistence with TranscriptStoreOptions controlling whether text, JSON, and JSONL writes happen, with an appendFile hook and a fallbackToFullWriteOnIncrementalFailure flag. There is an OVERSIZE_TRANSCRIPT_BLOB_THRESHOLD_BYTES constant set at 5,000,000, and the code handles Uint8Array serialization with a dedicated marker string. The agent package is dense: it imports BackgroundSummarizationMode, flushPostTurnEndedWork, DeferredInteractionResponseError, PrivacyCapability, PrivacyMode, redacted protos, a SummarizationOrchestrator, and a whole set of action handlers including UserMessageActionHandler, ResumeActionHandler, SubscriptionNotificationActionHandler, GoalContinuationActionHandler, SummarizeActionHandler, and ShellCommandActionHandler. The Electron main process in source/electron-main/main.ts defines typed interfaces for MainWebContents and MainBrowserWindow, handles DevTools gating, window state persistence, title bar overlays, and input event chords. The node-agent-coordinator package wires a gateway client, WebAuthn provider and signer, MCP OAuth forwarder, local exec daemon supervisor, transport stage recorder, and createCoordinatorInferenceRouter. These are not toy files.

The quality read from firsthand inspection is that this is a careful reconstruction with real internal structure and consistent type discipline. Every interface I opened uses readonly fields, union types, and explicit null returns. The rough edges are equally clear. The license is unknown, which is a real problem for anyone considering building on top of it. CI exists and is enabled, but the test suite has zero files and fails on exit, so CI is green only in the sense that there is nothing to run or it reports failure depending on configuration. The agent package alone imports from roughly thirty sibling modules, which means understanding the call graph requires real time. The reconstructed nature also means you are reading someone's interpretation of a shipped app, not the original source, so behavioral fidelity is unverified.

Who should use this: developers who want to study how a production AI desktop app structures its Electron, coordinator, and agent boundaries, and who are comfortable reading 365,000 lines of TypeScript to do it. The inference router and MCP tooling additions are practical if you want to route across Cursor, Claude Code, Codex, and OpenRouter. Where it bites: no license means no commercial use without legal review, zero tests mean you are on your own for verification, and npm test failing means CI signal is noise. This is a research artifact and a reading resource, not a dependency you pin.

What we ran

We installed and ran it ourselves. Here is what it took, the exact command, and the real output from our box. Nothing edited.

What it took: 1 attempt to get running.

#!/usr/bin/env bash
set -e
cd /tmp/rr/b-nnett_grok-bot-0.18-reconstructed

# Examine what's actually importable
ls source/packages/agent-transcript/ 2>/dev/null || true

# Try to find the actual source files (not just the excerpt)
find . -path ./node_modules -prune -o -name '*.ts' -print | head -30

# Check if there's a compiled JS version
find . -path ./node_modules -prune -o -name '*.js' -print | head -30

# Check for package.json scripts
cat package.json 2>/dev/null | head -40 || true

# Attempt to compile and import the core transcript module
if [ -f source/packages/agent-transcript/index.ts ]; then
    # Check if tsx or ts-node is available
    ls node_modules/.bin/tsx 2>/dev/null && echo "tsx available" || echo "no tsx"
    ls node_modules/.bin/tsc 2>/dev/null && echo "tsc available" || echo "no tsc"

    # Try running a minimal import via tsx
    cat > /tmp/test_transcript.ts <<'EOF'
import { stripContextTags } from "../tmp/rr/b-nnett_grok-bot-0.18-reconstructed/source/packages/agent-transcript/index.ts";

const input = "Here is a message <context>some context data</context> with tags";
const result = stripContextTags(input);
console.log("INPUT:", input);
console.log("OUTPUT:", result);
EOF

    npx tsx /tmp/test_transcript.ts 2>&1 || echo "tsx import failed"

    # Alternative: try to just parse and execute with node after compiling
    npx tsc --outDir /tmp/compiled source/packages/agent-transcript/index.ts 2>&1 || echo "tsc compile failed"

    # If compilation produced output, try running it
    if [ -f /tmp/compiled/agent-transcript/index.js ]; then
        node -e "
            const mod = require('/tmp/compiled/agent-transcript/index.js');
            console.log('Module exports:', Object.keys(mod));
            if (mod.stripContextTags) {
                const input = 'Hello <context>secret</context> world';
                console.log('INPUT:', input);
                console.log('OUTPUT:', mod.stripContextTags(input));
            }
        " 2>&1 || echo "node require failed"
    fi
else
    echo "No source/packages/agent-transcript/index.ts found"
    # Show the real tree structure
    find . -path ./node_modules -prune -o -type f -print | head -50
fi

echo "---"
echo "Done."
