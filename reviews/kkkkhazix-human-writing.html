I cloned KKKKhazix/human-writing this morning and read the source. It is a static code read only, not a run, because there is no runnable Python entrypoint in this repo. It is 640 lines of Python across 16 files, MIT licensed, with zero test files and no CI configured. 2748 stars and rising.

The project addresses a real problem in Chinese AI writing: model output reads smoothly but feels anonymous and templated. The repo provides a prose checker plus a writing/editing skill intended to make Chinese text sound like a specific person talking, with judgment and digressions. The README targets Zhihu-style content specifically.

Looking at scripts/check_prose.py, the core implementation is a rule-based linter for Chinese prose. It is organized around typed constant tuples that define banned patterns. HARD_JARGON is a list of corporate buzzwords like "赋能", "抓手", "底层逻辑", "降本增效", and "全链路". CONTEXT_JARGON is a softer list including "沉淀", "颗粒度", "对齐", and "闭环", words that are flagged depending on context. LYRIC_WORDS catches the literary affectation set: "安放", "抵达", "褶皱", "滚烫", "轻盈". HARD_STOPS bans opener phrases like "说白了" and "先说结论".

The pattern matching uses compiled regex groups. PIVOT_PATTERNS catches the "不是X而是Y" construction and its variants, a signature AI rhetorical tic. SEMANTIC_PIVOT_PATTERNS is more aggressive, targeting "总以为...其实", "回头看才发现", "真正...的是", and "不只...还" structures. NOMINALIZATION_PATTERNS flags "进行了" followed by abstract nouns like 调整, 优化, 升级, 复盘. FORBIDDEN_PUNCTUATION rejects colons and dashes. ROAD_SIGNS flags transitional phrases like "更微妙的是" and "需要指出的是". The docstring says it only warns, it does not auto-rewrite.

The architecture is a static rule engine. Every check is a tuple of patterns or a regex, and the script walks text and reports hits. The design choice to separate hard stops, context-dependent jargon, lyric words, and pivot patterns into distinct typed groups is clean and maintainable. Each group has a clear semantic category, and adding a new banned phrase means appending to a tuple.

Code quality from what I can see is functional and readable. The regex patterns are non-trivial and show someone who studied actual AI output failures in Chinese specifically. The character-class constraints inside patterns like [^。！？\n]{0,90} are careful about not over-matching across sentence boundaries. Error handling is absent because this is a checker, not a service. The obvious gap is the complete lack of tests: zero test files, no CI, and the regex patterns are complex enough that regressions are likely when someone extends them. There is no entry point that ties the skill into any AI framework, so the "ready to use" claim depends on files I did not examine.

This is for Chinese content writers and developers building Chinese AI writing tools who want to detect and strip machine-sounding patterns. The rule sets are specific and grounded in real failure modes. The star count reflects demand for exactly this. The missing test coverage and CI are the real weaknesses for anyone wanting to build on it.
