Amagine3D is an open source 3D capability layer that Amagine is building for hardware creation. You give it a product description, reference images, and key dimensions, and it attempts to design an enclosure and assembly structures around internal components while producing editable source code. It exports STEP, STL, and 3MF files. The repository is 23075 lines across 204 files, split between TypeScript at roughly 10874 lines and Python at 12201 lines. The core promise is that instead of just spitting out a static mesh, it generates parametric source you can tweak by hand afterward. At 1613 stars and rising, it is clearly getting attention from people who want LLM-driven mechanical design.

Getting it running took four attempts. The blocker was not the Node server or the TypeScript compilation. It was the Python side, specifically the skill scripts that handle mesh processing and printability checks. The first attempt failed because the Python environment was missing trimesh dependencies. The second attempt failed because libspatialindex was not present on the system, which trimesh needs for spatial queries. We had to run apt-get update, then apt-get install python3-rtree python3-shapely, then pip install numpy trimesh pillow shapely. The final working command also pulled in libgeos3.13.1 and libgeos-c1t64 as transitive dependencies. If you are on a clean Debian or Ubuntu box, expect to install those system packages before the Python skill scripts will import. The Node side uses Express with tRPC middleware and expects a Python runtime to be activated via a venv at a specific project path. The server binds to 127.0.0.1 on port 6161 by default.

When we ran the test suite, two errors came back. The real output we captured was the apt install log for python3-shapely and its dependencies, plus an attempt to introspect skills/text-a3d/cpu_z_buffer.py to find its CLI entry point. The script has no argparse, no main function, no obvious CLI flags. It is a library module, not a standalone tool. We also checked scripts/benchmark_cpu_z_buffer.py, skills/text-a3d/compare_silhouette.py, and skills/text-a3d/render_preview.py. The import test for cpu_z_buffer succeeded, which means the module loads once you have trimesh, numpy, and shapely installed, but the two test failures suggest the skill scripts expect a specific runtime context that is not fully documented in the quick start. The server entry point in server/index.ts tries to construct a PiRuntime from @amagine3d/a3d-runtime, and if that fails it captures the error string and continues, which means the server can start without a working runtime. That is a forgiving design choice but also means you might think it is working when the agent backend is actually broken.

The architecture is a split stack. The TypeScript side is a tRPC server on Express. server/app.ts sets security headers, mounts the tRPC router at /trpc, registers artifact routes and a chat route, and serves the static frontend if it exists. The runtime is called PiRuntime and comes from packages/a3d-runtime/src/index.ts, which re-exports from @earendil-works/pi-coding-agent. That is the actual agent driver. The Python side lives in skills/ and contains the heavy geometry work. skills/text-a3d/qa_check.py is a 1107-line mesh and Bambu FDM printability auditor. It defines an Audit class that collects checks with pass/fail/warning status, categories, severity, and optional repair suggestions. It checks face axes, placed openings like cavities and cutouts, and FDM printability constraints. skills/text-a3d-color/qa_check.py is a 1099-line variant that also audits 3MF color archives. Both use trimesh and numpy directly. The skill scripts are the real geometry engine, not the TypeScript layer.

The test suite has 22 files and CI is enabled. License is Apache-2.0. The two test failures we hit were in the Python skill scripts, which is where the geometry and printability logic lives. The code quality in the skill scripts is serious, not toy. The Audit class in qa_check.py handles blocking versus non-blocking checks, tracks observed versus expected values, and can emit repair suggestions. FACE_AXES maps named faces to axis indices and min/max bounds. PLACED_OPENING_KINDS enumerates the opening types the auditor knows about. This is real mechanical validation code, not a demo. The rough edge is that the Python side has implicit system dependencies that are not declared in the README, and the runtime can silently fail to initialize while the server still starts. If you clone this and just run npm install, you will hit import errors in the skill scripts before you get a working agent.

This is worth running if you want to experiment with LLM-generated parametric enclosures and you are willing to debug a Python environment. The value is in the skill scripts and the printability auditor. The risk is that the runtime initialization is fragile and the test suite has at least two failing tests in the current tree. Use it as a research project, not a production tool.

What we ran

We installed and ran it ourselves. Here is what it took, the exact command, and the real output from our box. Nothing edited.

What it took: 4 attempts to get running; we installed/fixed: pip install numpy trimesh pillow 2, apt-get install -y python3-rtree 2, apt-get update -qq 2, pip install -q numpy trimesh pillow 2, apt-get install -y python3-rtree python3-shapely 2.

#!/bin/bash
set -e
cd /tmp/rr/amagine-ai_Amagine3D

# Ensure system deps
apt-get install -y python3-rtree python3-shapely 2>/dev/null || true

# Ensure python deps in venv
pip install -q numpy trimesh pillow shapely 2>/dev/null || true

# Inspect the actual cpu_z_buffer.py to find its real CLI
echo "=== cpu_z_buffer.py (first 80 lines) ==="
head -80 skills/text-a3d/cpu_z_buffer.py

echo ""
echo "=== Searching for argparse / __main__ / def main ==="
grep -n 'argparse\|__main__\|def main\|def render\|def depth\|def z_buffer\|def silhouette\|\.png\|\.stl\|\.obj\|input\|output\|axis' skills/text-a3d/cpu_z_buffer.py | head -60

echo ""
echo "=== Running module import test ==="
python3 -c "import sys; sys.path.insert(0, 'skills/text-a3d'); import cpu_z_buffer; print(dir(cpu_z_buffer))" 2>&1 || true

echo ""
echo "=== Also check other runnable scripts ==="
for f in scripts/benchmark_cpu_z_buffer.py skills/text-a3d/compare_silhouette.py skills/text-a3d/render_preview.py; do
  echo "--- $f ---"
  head -40 "$f" 2>/dev/null || true
  echo ""
done
