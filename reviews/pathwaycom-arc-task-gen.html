I cloned pathwaycom/arc-task-gen and read the source. This is a static code review, not a run. The repository has no runnable entrypoint I could exercise end to end because every script requires an OpenAI-compatible API endpoint and an API key, and the project ships zero tests and no CI pipeline. I did not execute it.

The project generates original ARC-AGI-1-style grid transformation tasks that are distribution-matched to the public evaluation set. The motivation is that the real eval set has been scraped into training corpora, so frontier models may have memorised it. By producing fresh tasks that resemble the eval distribution in shape and colour profile, you get a private set a model cannot have seen. The README ties this to BDH-CQ, a post-Transformer recurrent architecture with evolving latent memory, but the code itself is model-agnostic. It targets any OpenAI-compatible chat completions endpoint, local or remote.

The core is generate_tasks.py at 906 lines. It imports httpx, numpy, and the openai client, and it spins up to 64 concurrent API workers via ThreadPoolExecutor to generate N=32 tasks per run by default. Each task is validated structurally and filtered through novelty checks against descriptions of the real eval tasks, which are produced by describe_eval_tasks.py. That 132-line helper sends up to three training pairs per task to the model and asks for a one to two sentence rule description, cached to data/arc_agi_eval_descriptions.json. A second helper, label_eval_tasks.py at 239 lines, assigns each eval task a coarse Chollet cognitive primitive category and a finer mechanic, cached to data/arc_agi_eval_categories.json. The stratified wrapper, generate_tasks_stratified.py, merges two older scripts and conditions generation on an anchor task's shape and colour statistics plus its category and optionally a target mechanic, allocating evenly across mechanics with --mechanics and --per-mechanic rather than leaving the natural skewed distribution. Notably, public grids, rule text, and task ids never enter the prompt, only statistics and labels do.

Code quality is readable and practical. The files have real docstrings with usage examples and environment variable notes. The concurrency model is straightforward: ThreadPoolExecutor over an OpenAI client with base_url override. Error handling is thin in what I can see, mostly bare try blocks with fallback on parse failures, and there is no retry or backoff logic visible in the excerpts. The zero-test, no-CI signal is the biggest gap for a tool that calls an LLM hundreds of times per run and writes cached JSON side effects. MIT licence is permissive and fine. This is for researchers building private ARC evaluation sets who already have API access and understand the cost. It is not plug and play, and it assumes you bring the toolchain.
