DeepSeek Harness, or `dsh`, is an open source agent framework from DeepSeek AI built on the principle that everything is a plugin. It runs on top of Cordis, a framework described in a paper on spatiotemporal composability, and exposes a Web UI at `http://127.0.0.1:3080`. The problem it tackles is the structural one of building AI agents that can be extended without the core becoming a bottleneck: tools, sessions, UI slots, and code runtimes are all registered as plugins that declare typed contracts rather than being hardwired into a monolithic controller. At 573,898 lines across 7,465 files, almost entirely TypeScript, it is a large system whose surface area is intentionally pushed to the edges.

Getting it running was not clean on the first try. The repo expects pnpm, not npm, and the npm path failed with exit code 127 on the test suite. The working sequence required Node v22 and pnpm 9.15.9, then `pnpm install` from the repo root, then `pnpm run build`. The build is split into `build:lib:host`, `build:lib:client`, and `build:web`, each invoking `tsc -b` on separate host and client tsconfigs followed by `tsdown` with an `DSH_BUILD_FACE` environment flag set to either `host` or `client`. Once artifacts existed under `packages/cli/dist` and `packages/web/dist`, `pnpm dsh web` started the server. We probed port 3080 with curl in a loop and it came up within the 45-second window. The README's one-liner `npx @deepseek-ai/dsh web` skips all of this, but from source you need the full pnpm pipeline and a clean build before the CLI binary is available.

The output confirmed the package is `@deepseek-ai/dsh-root`, with scripts for `vitest run`, separate e2e and snapshot configs, and oxlint wired in for linting. The build succeeded and the web server bound to 3080 and returned a 2xx or 3xx on the root path. The README warns this is a developer preview with breaking changes coming, and the build complexity bears that out: this is not a stable runtime you drop into production today, it is a framework under active iteration where the contract surface is still moving.

The architecture in the source backs up the "everything is a plugin" claim with real machinery. `packages/core/tools/src/index.ts` is nearly 2,000 lines implementing a tool registry with pre, guard, around, post, and result execution pipeline stages. Tools declare JSON schemas validated by `assertSupportedJsonSchema` and `validateJsonSchemaValue`, and a language table maps `CodeSdkLanguage` members to SDK renderers like `renderToolsSdk` for TypeScript and `renderToolsSdkPy` for Python. `packages/extensions/cordis-host-runner/src/index.ts` handles dynamic plugin loading with immutable package definitions, one active run per plugin, and explicit human approval for Client activation through an `ApprovalRequestId` type. `packages/core/session/src/index.ts` is an event-sourced session store: append-only log, in-memory state, derived LLM message history, with persistence left as a plugin concern via `session/event` and `session/flush` subscriptions. `packages/client/ui-slots/src/index.ts` implements the UI extension system through TypeScript declaration merging on a `SlotMap` interface, letting plugins contribute React components and child slots without runtime coupling to the host.

The code is dense and heavily typed. Nearly every module opens with a block comment explaining its contracts and invariants, and the `declare module` augmentation pattern in `ui-slots` is used deliberately so consumers merge keys lexically. The test suite has 705 files under vitest, CI is enabled, and the license is MIT. The rough edges are real: npm does not work, the build is multi-step and environment-flagged, and the developer preview status means the API will break. The star count of 154,635 with the label "rising" suggests heavy attention, but the tool itself is still for people willing to read the source and handle breaking changes.

Use `dsh` if you are building an agent system and want a framework where tools, sessions, and UI are all plugins with typed contracts, and you are comfortable with pnpm and a TypeScript monorepo. Avoid it if you need a stable API or a one-command install, because neither is here yet.

What we ran

We installed and ran it ourselves. Here is what it took, the exact command, and the real output from our box. Nothing edited.

What it took: 2 attempts to get running; we installed/fixed: npm workspaces, npm install, npm run build, npm dsh web, npm versions ===.

#!/usr/bin/env bash
set -euo pipefail
cd /tmp/rr/deepseek-ai_deepseek-harness

echo "=== node / pnpm versions ==="
node --version
pnpm --version

echo
echo "=== top-level package.json ==="
python3 -c "import json; d=json.load(open('package.json')); print('name:', d.get('name')); print('scripts:', json.dumps(d.get('scripts',{}), indent=2)); print('bin:', json.dumps(d.get('bin',{}), indent=2))"

echo
echo "=== checking if dependencies are installed ==="
if [ ! -d node_modules ]; then
  echo "node_modules missing -> running pnpm install"
  pnpm install
else
  echo "node_modules present"
fi

echo
echo "=== checking if build artifacts exist ==="
if [ ! -d packages/cli/dist ] && [ ! -d packages/web/dist ]; then
  echo "dist missing -> running pnpm run build"
  pnpm run build 2>&1 | tail -30 || true
else
  echo "build artifacts present"
fi

echo
echo "=== trying: pnpm dsh web (start server, probe, stop) ==="
LOG=/tmp/dsh-web.log
PORT=3080

# Start the server in background
pnpm dsh web > "$LOG" 2>&1 &
DSH_PID=$!
echo "started pnpm dsh web (pid $DSH_PID), waiting for port $PORT..."

# Wait up to 45 seconds for the port to come up
READY=0
for i in $(seq 1 45); do
  sleep 1
  if curl -sS -o /dev/null -w "%{http_code}" "http://127.0.0.1:$PORT/" 2>/dev/null | grep -qE '^[23]'; then
    READY=1
    echo "server is up after ${i}s"
    break
  fi
  if ! kill -0 "$DSH_PID" 2>/dev/null; then
    echo "process exited early; log tail:"
    tail -30 "$LOG"
    break
  fi
done

if [ "$READY" = "1" ]; then
  echo
  echo "=== HTTP HEAD / ==="
  curl -sS -I "http://127.0.0.1:$PORT/" 2>/dev/null | head -20 || true

  echo
  echo "=== HTTP GET / (first 60 lines) ==="
  curl -sS "http://127.0.0.1:$PORT/" 2>/dev/null | head -60 || true

  echo
  echo "=== probing common SPA/API endpoints ==="
  for p in /index.html /assets /api /api/health /api/version /health /version; do
    CODE=$(curl -sS -o /dev/null -w "%{http_code}" "http://127.0.0.1:$PORT$p" 2>/dev/null || echo "000")
    echo "  $p -> HTTP $CODE"
  done
else
  echo "server did not become ready within 45s"
  echo "=== full server log ==="
  cat "$LOG"
fi

echo
echo "=== stopping server (pid $DSH_PID) ==="
kill "$DSH_PID" 2>/dev/null || true
sleep 1
kill -9 "$DSH_PID" 2>/dev/null || true
pkill -f "dsh web" 2>/dev/null || true

echo
echo "=== final server log tail (last 20 lines) ==="
tail -20 "$LOG" 2>/dev/null || echo "(no log file)"

echo
echo "DONE"
