DeepSeek Harness is an agent framework built on the idea that everything is a plugin. It is a TypeScript project from DeepSeek AI that uses a custom scheduler called Cordis to manage agent tools, sessions, and user interfaces. The framework is still in a developer preview stage and the maintainers warn that breaking changes are coming. It targets developers who want to build AI agents where tools, code execution, and user interface slots are all dynamically registered and strictly scoped.

Getting it running on our box took two attempts. The repository requires pnpm, which is the first hurdle if you are used to npm. The test suite itself reported an exit code 127 when we tried running it with npm, because npm was not found in the expected environment. We had to install dependencies with `pnpm install`, build the project with `pnpm run build`, and then start the web server using `npx @deepseek-ai/dsh web --no-open`. The build step prepares repository artifacts that the `pnpm dsh web` command uses directly without rebuilding. The `--no-open` flag prevents the command from trying to launch a local browser, which is useful for headless servers or remote SSH sessions where only the host URL should be printed. The setup is not just a simple npm install and you are done. You need the pnpm package manager and the correct Node.js environment or the scripts fail immediately.

When we started the server, it launched on port 3080 as documented. We polled the root URL and got a response. The actual output we observed was a JSON manifest of client plugins. It listed plugins like `@deepseek-ai/dsh-client-ui-settings`, `@deepseek-ai/dsh-client-ui-plan`, and `@deepseek-ai/dsh-client-ui-trajectory`, each with a specific URL path, a revision hash, and a list of injection dependencies. For example, the user questions plugin depends on `@deepseek-ai/dsh-client-locale` and `@deepseek-ai/dsh-client-ui-conversation`. The theme plugin loads immediately. This output shows the tool delivers on its core claim. The system is literally loading and serving a web interface composed entirely of individually registered plugins with explicit dependency injection. You are looking at the plugin architecture working in real time.

The source code backs this up. The `packages/core/tools/src/index.ts` file contains nearly two thousand lines defining a tool registry and an execution pipeline with guard and post phases. It uses a schemastery validation layer and a scope system from `@deepseek-ai/dsh-scope` to manage context. The `packages/core/session/src/index.ts` file implements an event sourced session service. It keeps an append only session log and derives LLM message history from it, leaving persistence as a separate plugin concern. The `packages/client/ui-slots/src/index.ts` file provides a slot registry for the user interface where components declare child slots and store seats. The `packages/extensions/cordis-host-runner/src/index.ts` file handles dynamic plugin activation with human approval gates and Host and Client invocation separation. The architecture is strict and compartmentalized.

The codebase is large at over six hundred thousand lines across nearly eight thousand files, with seven hundred and forty five test files and CI enabled. The MIT license is permissive. The quality of the code is visible in the strong typing and explicit dependency declaration, but the developer preview status shows. The tool suite did not run cleanly for us out of the box and required manual environment fixing. The documentation is bilingual which helps, but the rapid iteration warning in the README is something to take literally.

This framework is for developers who want a highly structured, plugin driven agent harness and are willing to work with pnpm and a fast changing codebase. It bites when you expect a stable API or try to use standard npm workflows. The architecture is impressive and the plugin system is real, but you are adopting an early stage tool that will shift under you. Use it to build agent systems where you control the full stack, not for production stability today.

We installed and ran it ourselves. Here is what it took, the exact command, and the real output from our box. Nothing edited.

#!/usr/bin/env bash
set -euo pipefail
cd /tmp/rr/deepseek-ai_deepseek-harness

export PATH="/tmp/rr/deepseek-ai_deepseek-harness/.rrvenv/bin:$PATH"

echo "=== installing deps ==="
pnpm install 2>&1 | tail -40

echo "=== building ==="
pnpm run build 2>&1 | tail -60

echo "=== checking for dsh binary ==="
ls -la node_modules/.bin/dsh 2>/dev/null || true
ls -la node_modules/.bin/ 2>/dev/null | head -20 || true
find . -name "dsh" -path "*/bin/*" 2>/dev/null | head -5 || true

echo "=== trying npx path ==="
which npx
# Start the server in background, capture all output
LOGFILE="/tmp/dsh_web.log"
npx @deepseek-ai/dsh web --no-open > "$LOGFILE" 2>&1 &
DSH_PID=$!
echo "Started dsh web with PID $DSH_PID"

# Wait for the port to come up
echo "=== waiting for server on port 3080 ==="
for i in $(seq 1 30); do
  if curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3080/ 2>/dev/null | grep -qE "^(200|302|404)$"; then
    echo "Server responded after ${i}s"
    break
  fi
  sleep 1
  if ! kill -0 $DSH_PID 2>/dev/null; then
    echo "Process died early. Log output:"
    cat "$LOGFILE"
    exit 1
  fi
done

echo "=== curl the root ==="
curl -s -i http://127.0.0.1:3080/ 2>&1 | head -30 || true

echo "=== curl a static/asset path ==="
curl -s -i http://127.0.0.1:3080/index.html 2>&1 | head -20 || true

echo "=== full server log ==="
cat "$LOGFILE"

echo "=== killing server ==="
kill $DSH_PID 2>/dev/null || true
wait $DSH_PID 2>/dev/null || true

echo "=== done ==="
