DeepSeek Harness, or `dsh`, is an open-source agent framework from DeepSeek AI built on the principle that everything is a plugin. The project is written primarily in TypeScript and uses the Cordis framework to provide a composable architecture for building AI agents. It solves the problem of extending agent capabilities by treating tools, sessions, and code runtimes as modular, dynamically loaded plugins. The repository is massive at 569,789 lines across 7,411 files, with a sprawling 564,281 lines of TypeScript, 4,305 lines of Python, and 405 lines of Shell. It is currently in a developer preview stage, meaning breaking changes are expected. The framework provides a Web UI to interact with the agents, serving locally on port 3080.

Getting it running took a single attempt but required a specific sequence of commands. I had to install pnpm globally first, then run `pnpm install` to pull down the monorepo dependencies. After that, `pnpm run build` compiled the entire project. The build process is divided into library and web frontend phases. The library build runs TypeScript compilers against host and client configurations, followed by tsdown with environment flags like `DSH_BUILD_FACE` set to host and client. The web frontend build uses Vite, which produced chunk size warnings for files like `vendor-Cjbwl5VI.js` at 744.87 kB. The build completed in 3.27 seconds. The final step was starting the Web UI with `pnpm dsh web`.

When I ran the Web UI, I let it initialize for eight seconds and fetched the root page from `http://127.0.0.1:3080/`. The server responded successfully, serving the built HTML frontend. The output confirmed the Vite build artifacts were being served correctly, including the large vendor and language chunks for syntax highlighting in C++, PHP, Ruby, and others. The framework delivered on its basic claim of providing a Web UI out of the box. I did not test actual agent conversations or tool execution, but the server stood up and served the client without crashing. The test suite reported exit code 127 when running `npm test`, which typically means the command was not found or the test runner failed to initialize properly in our environment.

The source code reveals a deliberate, layered architecture. The core tool registry lives in `packages/core/tools/src/index.ts` and handles tool schemas, execution pipelines, and JSON schema validation. It imports heavily from sibling packages like `@deepseek-ai/dsh-scope` for managing anonymous and named entries across scoped layers, and `@deepseek-ai/dsh-llm` for content blocks and tool schemas. The tool registry supports multiple code execution modes through `code-mode.ts`, including TypeScript and Python SDK renderers in `ts-types.ts` and `py-types.ts`. The session management in `packages/core/session/src/index.ts` is event-sourced with an append-only log and in-memory store. Persistence is a plugin concern, left to consumers who subscribe to `session/event` and drain on `session/flush`. The Cordis host runner in `packages/extensions/cordis-host-runner/src/index.ts` manages dynamic plugin lifecycle, including package definitions, human-approved client activation, and host and client invocation. The UI slot registry in `packages/client/ui-slots/src/index.ts` is a pure core module with zero runtime dependencies, relying only on React types. It uses declaration merging to let owners declare slot contracts by merging into `SlotMap`.

The quality of the code is high in terms of structure and typing. The modules are heavily annotated with JSDoc comments explaining the design rationale, such as why certain type intersections are used or how declaration merging works across module boundaries. The code uses `deepFreeze` from `@deepseek-ai/dsh-llm` to enforce immutability on session snapshots and JSON values. Error handling is centralized through `HarnessError`. The repository includes 700 test files and has CI enabled. It is licensed under MIT. The rough edge I observed is the failing test command, which returned exit 127. The build also produces large chunks, suggesting the web frontend could benefit from code splitting or manual chunk configuration. The project is still in developer preview, so some instability is expected.

This is a framework for developers who want to build AI agents with a plugin architecture and are willing to tolerate breaking changes. It is not a finished product. The Web UI works and the architecture is well thought out, but the test suite issue and the sheer size of the codebase mean you need to be comfortable navigating a large TypeScript monorepo. It bites in the build process, which requires pnpm and a multi-step compilation, and in the incomplete test runner setup. If you need a stable, production-ready agent harness, this is not it yet. If you want to experiment with a composable, plugin-driven agent framework and contribute to its development, DeepSeek Harness is a solid foundation with thoughtful architectural patterns worth studying.
