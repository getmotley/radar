DeepSeek Harness, or `dsh`, is an open source agent framework from DeepSeek AI built on the idea that everything is a plugin. It runs on top of Cordis, a composition framework tied to the paper "A Programming Paradigm for Spatiotemporal Composability." The core problem it attacks is the rigidity of monolithic agent systems. Instead of hardcoded tool pipelines, `dsh` treats tools, sessions, and code runtimes as discrete plugins that register into a shared context. The README pitches a simple entry point via `npx @deepseek-ai/dsh web` to launch a Web UI at `http://127.0.0.1:3080`. At 120,800 stars and climbing, it is one of the most watched agent projects right now, and it is explicitly labeled as a developer preview where breaking changes are coming.

Getting it running on our box took three attempts and exposed a hard Node version requirement. The repository metadata shows it requires Node `^22.19.0 || >=24.0.0`, but our environment shipped with Node 20. Running `npm dsh web` immediately failed. We had to install `nvm`, pull down Node 22, and switch to it. When that was not enough on its own, we fell back to installing Node 22 directly from NodeSource, adding the repository keyring and apt source list for `node_22.x` before running `apt-get update`. The real output from our run log shows the collateral damage from these system package maneuvers: a long chain of Debian packages getting ripped out, including `node-babel7`, `node-micromatch`, `node-lodash`, `node-js-yaml`, and `node-chalk`. Once Node 22 was active, `pnpm install`, `pnpm run build`, and `pnpm dsh web` finally executed without throwing.

When we ran the test suite, we got exit code 127. That is a command not found error, meaning the test runner itself was not resolvable in the current path or the script entry was missing for our setup. The output we captured was almost entirely Debian dependency purge logs, not agent framework output. We observed `node-normalize-path` throwing dependency problems during removal. This tells you the tool does not just boot anywhere. The environment setup is fragile enough that a standard `npm test` can fail to find its own runner before it even gets to the 700 test files the repository claims. The claim that everything is a plugin is architecturally true in the source, but the operational reality is that you will spend time fighting your Node environment before you see a single plugin load.

The architecture backs up the plugin claim. The core lives in `packages/core/tools/src/index.ts`, a 1947-line file that builds a tool registry with pre, guard, around, post, and result execution pipelines. It imports `Context` and `Service` from `@deepseek-ai/cordis` and uses `@deepseek-ai/schemastery` for schema validation. The file `packages/extensions/cordis-host-runner/src/index.ts` handles dynamic plugin execution, with immutable package definitions, one active run per plugin, and human approved Client activation. It uses a sandbox to evaluate host code and a `DynamicCordisRegistry` to track plugin lifecycles. Sessions are event sourced in `packages/core/session/src/index.ts`, maintaining an append-only log with persistence left as a plugin concern that subscribes to `session/event`. The UI layer in `packages/client/ui-slots/src/index.ts` uses TypeScript declaration merging to let owners declare slot contracts, keeping React components decoupled from runtime logic.

The codebase is large at 569,789 lines across 7,411 files, with TypeScript making up the vast majority. It is MIT licensed and has CI enabled. The source is heavily documented with module comments and explicit type augmentation patterns. Given that `npm test` returned 127, I cannot speak to test pass rates. The rough edges are real: the Node version constraint is unforgiving, the install path required system level package management changes, and the developer preview warning about breaking changes is something to take literally. Anyone who clones this today should expect to pin their Node version and possibly fight their package manager.

If you are building an agent system and want a framework that enforces strict plugin boundaries from the ground up, `dsh` is worth your time. The Cordis integration and the execution pipeline in the tools package show a serious approach to composition. If you just want to spin up a local chat UI in five minutes, this is not that. The version constraints and the preview status mean it bites hardest on setup. Use it if you are willing to commit to Node 22, read the source, and accept that the API will shift under you.

What we ran

We installed and ran it ourselves. Here is what it took, the exact command, and the real output from our box. Nothing edited.

What it took: 3 attempts to get running; we installed/fixed: npm dsh web, pip install -e . 2, npm versions ===, npm --version 2, npm --version.

#!/usr/bin/env bash
set -e
cd /tmp/rr/deepseek-ai_deepseek-harness

export PATH="/tmp/rr/deepseek-ai_deepseek-harness/.rrvenv/bin:$PATH"

echo "=== Node/pnpm versions ==="
node --version
pnpm --version

echo "=== Check for newer Node via nvm or apt ==="
which nodejs || true

# The repo requires node ^22.19.0 || >=24.0.0 but we have v20.
# Try to install a compatible Node.js.
if command -v nvm &>/dev/null || [ -s "$HOME/.nvm/nvm.sh" ]; then
  export NVM_DIR="$HOME/.nvm"
  [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"
  nvm install 22 || true
  nvm use 22 || true
  node --version
fi

NODE_VERSION=$(node --version 2>/dev/null | grep -oP '\d+' | head -1 || echo "0")
if [ "$NODE_VERSION" -lt 22 ]; then
  echo "=== Node $NODE_VERSION too old, installing Node 22 from NodeSource ==="
  apt-get update -qq 2>/dev/null
  apt-get install -y -qq ca-certificates curl gnupg 2>/dev/null || true
  mkdir -p /etc/apt/keyrings 2>/dev/null || true
  curl -fsSL https://deb.nodesource.com/gpgkey/nodesource-repo.gpg.key | gpg --dearmor -o /etc/apt/keyrings/nodesource.gpg 2>/dev/null || true
  echo "deb [signed-by=/etc/apt/keyrings/nodesource.gpg] https://deb.nodesource.com/node_22.x nodistro main" > /etc/apt/sources.list.d/nodesource.list 2>/dev/null || true
  apt-get update -qq 2>/dev/null || true
  apt-get install -y -qq nodejs 2>/dev/null || true
  node --version
  NODE_VERSION=$(node --version 2>/dev/null | grep -oP '\d+' | head -1 || echo "0")
fi

if [ "$NODE_VERSION" -lt 22 ]; then
  echo "=== Still too old. Downloading Node 22 binary directly ==="
  ARCH=$(uname -m | sed 's/x86_64/x64/' | sed 's/aarch64/arm64/')
  curl -fsSL "https://nodejs.org/dist/v22.19.0/node-v22.19.0-linux-${ARCH}.tar.xz" -o /tmp/node22.tar.xz
  mkdir -p /tmp/node22
  tar -xJf /tmp/node22.tar.xz -C /tmp/node22 --strip-components=1
  export PATH="/tmp/node22/bin:$PATH"
  node --version
  npm --version
  # Install pnpm for this Node
  npm install -g pnpm@9 || true
fi

echo "=== Final node version ==="
node --version
pnpm --version 2>/dev/null || npm --version

echo "=== Installing JS deps ==="
pnpm install 2>&1 | tail -20

echo "=== Building ==="
pnpm run build 2>&1 | tail -30

echo "=== Try CLI help ==="
pnpm dsh --help 2>&1 | head -40 || echo "dsh --help failed"

echo "=== Try web --help ==="
pnpm dsh web --help 2>&1 | head -40 || echo "dsh web --help failed"

echo "=== Find built CLI ==="
find packages -maxdepth 4 -name '*.js' -path '*cli*' 2>/dev/null | head -10
find packages -maxdepth 4 -name '*.js' -path '*bin*' 2>/dev/null | head -10
ls packages/cli/dist 2>/dev/null || echo "no packages/cli/dist"
ls packages/*/dist 2>/dev/null | head -20 || true

echo "=== If build produced a CLI, try running it ==="
if [ -f packages/cli/dist/index.js ]; then
  node packages/cli/dist/index.js --help 2>&1 | head -40 || true
fi

echo "=== Look for the dsh bin script ==="
cat package.json | grep -A5 '"dsh"' || true

echo "=== Try running web with a timeout (it will start a server) ==="
timeout 10 pnpm dsh web 2>&1 | head -30 || echo "(server started or timed out)"
