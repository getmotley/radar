I cloned deepseek-ai/deepseek-harness to see what a 196k-star agent framework actually looks like on disk. It is a big TypeScript monorepo: 622,317 lines across 7,902 files, with 760 test files, MIT licensed, CI enabled. The pitch is "everything is a plugin," powered by Cordis, and the README tells you to run `npx @deepseek-ai/dsh web` or build from source with `pnpm install`, `pnpm run build`, `pnpm dsh web`. I tried both. I could not get it to run.

I started with `npx @deepseek-ai/dsh web`. Node was present but the npm invocation returned exit 127, meaning the command binary was not found on PATH in that shell. I installed pnpm globally and ran `pnpm install`, which pulled dependencies for the monorepo. Then `pnpm run build` failed with a non-zero exit across the workspace. I retried with `npm install` followed by `npm run build` and hit the same wall. The build never completed, so `pnpm dsh web` and `npm dsh web` never started the server on port 3080. I made five attempts, fixing environment issues between them, and the last error was still a failed build. I cannot tell you what the Web UI looks like because I never saw it load.

The source itself is serious and specific, not a weekend project. `packages/core/tools/src/index.ts` is 1,947 lines implementing a tool registry with pre, guard, around, post, and result execution stages, plus model presentation modes. It pulls in `@deepseek-ai/dsh-scope` for anonymous and named entries, scoped layers, and scope targeting. It validates JSON schemas via `assertSupportedJsonSchema` and `validateJsonSchemaValue`, renders TypeScript SDK types through `renderToolsSdk`, and Python types through `renderToolsSdkPy`. The code is commented at a level I rarely see: the file explains that adding a backend language requires three parallel edits, a `CodeSdkLanguage` member, a renderer entry, and a `RUN_CODE_FLAVORS` entry in `code-mode.ts`. That is the kind of comment written by someone maintaining it, not generated filler.

`packages/extensions/cordis-host-runner/src/index.ts` is 1,275 lines implementing the dynamic plugin runtime. It defines immutable package definitions, allows one active run per plugin, requires human approval for client activation, and handles host and client invocation through `TypertRemoteService` and `Remote` from `@deepseek-ai/dsh-typert-protocol`. It uses a sandbox (`createSandbox`, `evaluateHostCode`, `precheckCode`) and a registry (`DynamicCordisRegistry`) that tracks plugin definitions, pending requests, runs, and inspection state. The type surface exported from `types.ts` is dense: `DynamicCordisDefineReceipt`, `DynamicCordisPluginInspection`, `DynamicCordisRunResolution`, and on. This is a protocol layer, not a script.

`packages/core/session/src/index.ts` is 1,158 lines implementing an event-sourced session log. It is append-only, keeps an in-memory store, and derives LLM message history from events. Persistence is left to plugins that subscribe to `session/event` and drain on `session/flush`. It exports `snapshotJsonValue`, `SurfaceManager`, `foldRequestHeader`, `canonicalHeader`, and chunk row encoding through `decodeStorageRecord` and `packChunkRuns`. The design is clear: the session is a log, the surface is derived, persistence is someone else's concern.

`packages/client/ui-slots/src/index.ts` is 1,193 lines of slot registry with zero runtime dependencies beyond React types. Owners declare slot contracts through declaration merging on `SlotMap` and `LocaleNamespaceMap`. The `Translate` type narrows dictionary keys to the owning namespace union. The file comments acknowledge the awkwardness of `keyof SlotMap & string` collapsing to `never` in isolation and explain why `oxlint-disable` suppresses the false positive.

The quality signals are strong on the page: 760 test files, CI enabled, TypeScript dominant with Python and Shell in supporting roles, MIT license, and code comments that read like engineering notes. But I could not build it across five attempts, and the README's developer preview warning that breaking changes are coming means the install path may be fragile right now. If you want to try it, `npx @deepseek-ai/dsh web` is the path of least resistance and worth a shot first. Building from source requires a working pnpm workspace build that I could not produce today. The framework looks like a real, large-scale agent system. I just cannot confirm it runs, because it did not run for me.
