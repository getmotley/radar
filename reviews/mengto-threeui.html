MengTo/threeui

TypeScript★ 4.2kMIT28,422 LOCran ✓ npm test exit 1

I cloned MengTo/threeui today, 4239 stars and rising, and got it building on our box after several attempts. It is the open-source, login-free edition of the ThreeUI component catalog, a TypeScript and React library of interactive Three.js components and landing pages. The README is upfront that this is the Community edition, meaning Pro and Beta components are stripped out and every free variant and control is retained. The problem it solves is giving developers a library of production-grade Three.js scenes and UI effects they can drop into a project without paying or logging in. The index file alone exports roughly forty components ranging from AmberHalftone and AnimatedTopDock to CharacterCarousel, ConstellationField, and EmberStorm.

Getting it running took four attempts. The test suite reported exit 1 on npm test, which was not encouraging. The sequence of commands that eventually worked was npm run build repeated a few times until it produced lib-dist cleanly. The exact final command was a bash script running npm run build with output redirected to a file, then probing the resulting artifacts. Build exit code came back 0 and the build finished in 1.70 seconds, copying Community runtime documents and assets to lib-dist/assets. No system libraries were missing and no dependency installs failed. The friction was entirely in figuring out which build command to trust given the test suite failure and the multiple scripts in package.json.

The build produced 678 files in lib-dist, which is substantial. The largest artifact was synthralos-halftone.html at 17 megabytes, followed by bestsellers-book-showcase.html at 3.4 megabytes and landscape.html at 2.4 megabytes. Gallery.js came in at 1.5 megabytes and is real compiled JavaScript, opening with imports from react/jsx-runtime and three, then jumping straight into base64-encoded WebP image data embedded as URLs. The source-code.json spot check produced no output, suggesting either it did not exist at that path or was empty, which is worth noting if you expect to browse component source through the UI. The dev script is just vite, and package.json exposes scripts for sync:community, generate:lib, typecheck, build:site, and build:lib alongside the test and audit commands. The build clearly delivers on the catalog promise: these are full self-contained HTML documents with embedded Three.js runtimes, fonts, images, and audio assets, not minimal code samples.

The architecture is interesting and somewhat unusual. src/index.ts is auto-generated by scripts/generate-library-entry.mjs and explicitly says do not edit by hand. It imports a community.css shader file and re-exports every component from src/package-components/. The real heavy lifting lives in src/shaders/temple-night/templeNightRenderer.js, a 2537-line generated file that reconstructs a complete Three.js world from a canonical HTML source verified by SHA-256 hash. It includes its own math utilities like mulberry32 for deterministic randomness, noise2D for gradient noise, frame-rate-independent damping via the damp function, and respects prefers-reduced-motion and hover capabilities through matchMedia queries. Another major file, src/shaders/neuform-isolated/NeuformIsolatedEffects.tsx at 1368 lines, imports 28 raw HTML sources as strings using Vite's ?raw suffix, each a self-contained effect document. There is also a skill markdown generator at src/components/buildSkillMarkdown.js that produces structured instructions for AI agents to reconstruct specific effects like the Kage temple experience byte-for-byte from verified source, complete with SHA-256 revision identifiers.

The codebase is 28422 lines across 411 files, 22689 of which are TypeScript with 5733 lines of JavaScript. The templeNightRenderer.js file is marked as generated from committed source and explicitly excludes HTML page UI, chapter card viewports, and cloth cards from the Three.js world extraction. The test situation is weak: zero test files in the library itself, and the npm test command that runs community-sanitizers, public-boundary, library-package, and prepare-community-release scripts exits with code 1. CI is configured and the license is MIT, which is clean. The sponsorship model in the README starts at $500 per month for README links and $1500 per month for website placements, which tells you this is a monetized project with the Community edition as the free tier.

The rough edges are real. The 17 megabyte single HTML file for one component is a lot of weight. The failed test suite on a clean clone is not confidence-inspiring even if the build itself succeeds. The auto-generated index file means you should never hand-edit the entry point. And the source-code.json probe returning nothing suggests the in-UI source browser may have gaps. For developers who want a catalog of visually rich Three.js components to study, adapt, or ship, this is a genuine resource. For teams wanting a tested, lightweight dependency, the zero test files, the heavy embedded assets, and the exit 1 on test are reasons to look carefully before committing.

#!/usr/bin/env bash
set -euo pipefail

cd /tmp/rr/MengTo_threeui

echo "=== MengTo/threeui: build + dev server ==="
echo ""

npm run build > /tmp/build_output.txt 2>&1

echo "Build exit code: $BUILD_EXIT"
echo ""

echo "--- Build summary (last 3 lines) ---"
tail -3 /tmp/build_output.txt

echo ""

echo "=== Largest artifacts ==="

echo "=== Spot-check: source-code.json exists and is real ==="
if [ -f lib-dist/assets/source-code.json ]; then
    ls -lh lib-dist/assets/source-code.json
    python3 -c "import json; d=json.load(open('lib-dist/assets/source-code.json')); print('Top-level keys:', list(d.keys())[:10])" 2>/dev/null || head -c 200 lib-dist/assets/source-code.json
    echo ""

echo "=== Spot-check: Gallery.js is real JS ==="
head -c 300 lib-dist/shaders/gallery/Gallery.js 2>/dev/null || true
echo ""

echo "=== Check package.json for dev script ==="
python3 -c "import json; p=json.load(open('package.json')); s=p.get('scripts',{}); print('scripts:', json.dumps(s, indent=2))"
echo ""

echo "--- Starting dev server (10s probe) ---"
set +e
timeout 15 npm run dev > /tmp/dev_output.txt 2>&1 &
DEV_PID=$!
sleep 10

# Try to fetch whatever the dev server is serving
set +e
DEV_URL=$(grep -oP 'http://localhost:\d+' /tmp/dev_output.txt | head -1)
if [ -n "$DEV_URL" ]; then
    HTTP_CODE=$(curl -s -o /tmp/dev_page.html -w '%{http_code}' "$DEV_URL" 2>/dev/null)
    echo "Dev server URL: $DEV_URL"
    echo "HTTP status: $HTTP_CODE"
    echo "Page size: $(wc -c < /tmp/dev_page.html) bytes"
    echo "--- First 500 chars of served page ---"
    head -c 500 /tmp/dev_page.html
    echo ""
else
    echo "No dev server URL found in output"
    echo "--- Dev output ---"
    cat /tmp/dev_output.txt
fi

kill $DEV_PID 2>/dev/null || true
wait $DEV_PID 2>/dev/null || true
set -e

echo ""
echo "=== Done ==="
