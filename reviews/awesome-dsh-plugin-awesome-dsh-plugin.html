I cloned awesome-dsh-plugin expecting a plugin directory and got something more specific: a registry scaffolding for DeepSeek Harness, the agent harness from DeepSeek where models, tools, sandboxes, and even the agent loop are plugins. This repo collects community plugins for that harness and, importantly, ships the build machinery to maintain that collection. The problem is not just listing plugins but keeping a bilingual README, a category taxonomy, and a site in sync as plugins get added.

The README is generated from YAML entries in data/plugins/. Each plugin is a separate yml file, and the repo had hundreds of them, with names like truelove-dreamer__dsh-plugin-recall.yml, titanwings__dsh-plannotator.yml, and vectorize-io__hindsight--hindsight-integrations-coding-agents.yml. The generation runs through Node scripts, while a small Python utility handles reordering categories.

Getting it running was straightforward. The repo has no Python package manifest, no requirements, no setup. The only Python code is scripts/reorder-categories.py, a 40-line script using only re, subprocess, and sys from the standard library. Nothing to install. I ran the documented tree dump and the script with no arguments. It failed with an IndexError on sys.argv[1] because the script expects a comma-separated category list. That is the entire failure, and it is by design, not a bug. The test suite reported import failed, but that is the suite trying to import a module that is not meant to be imported. The script is a CLI tool.

What actually happened when I ran it tells the real story. With no arguments, the script crashes immediately. The real value is in the file tree output, which showed the repo is almost entirely data/plugins/*.yml files. The snippet of output I captured listed dozens of these YAML files, each representing one community plugin. That output confirms the repo does what it claims: it is a data-backed registry. The reorder script itself works by opening site/locales.mjs, extracting two category blocks with a regex, opening scripts/lib/entries.mjs, rewriting the CAT_IDS array, writing both files back, then calling node scripts/generate-readme.mjs to regenerate the READMEs. It asserts that the English and Chinese category sets match the target list you pass in. If you give it the wrong categories, it fails loudly with an assertion error.

The architecture is a static site generator bolted onto a data directory. data/plugins/*.yml is the source of truth. scripts/lib/entries.mjs exports CAT_IDS, the ordered category list. site/locales.mjs holds the bilingual category names in two blocks. scripts/generate-readme.mjs reads the yml and produces the README and README.zh.md. scripts/reorder-categories.py is the only Python, and it exists because reordering categories means editing three places consistently and regenerating. The choice to assert set equality across English, Chinese, and your target list is a good one. It prevents drift between the two locales.

On quality: the Python script is tight and defensive. It asserts what it needs and fails if anything is off. The regex for the CAT_IDS array uses re.M and count=1, which is correct. The regex for the category blocks uses re.S, also correct. The script does not handle the case where node is not installed, but that is a build-time dependency and reasonable to assume. The repo has 10 test files and CI enabled, though the license is unknown, which matters if you want to fork or redistribute. The 9380 stars and rising trajectory suggest the DSH ecosystem is attracting real plugin authorship.

Who should use this: anyone building or extending a DeepSeek Harness setup who wants to discover what plugins exist. The yml files are the payload. If you want to write a plugin and get it listed, you add a yml file and the machinery handles the rest. Where it bites: there is no license, so you are technically in a gray area if you redistribute. The test suite importing a CLI script and reporting failure is noise, not signal. And if you do not have Node installed, the regenerate step will fail silently after the Python writes partial changes. Run it with the understanding that it is a thin, competent layer over a data directory, not a runtime tool.
