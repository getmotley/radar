I cloned awesome-dsh-plugin today expecting a plugin directory and found something more specific. It is a curated list of community plugins for DeepSeek Harness, the agent framework DeepSeek open sourced where everything from models and tools to sandboxing and session storage is a plugin. The repo lists entries installable via `dsh plugin add`, each declaring a `dsh.bundle` manifest. The problem it solves is discovery: as the harness ecosystem grows, developers need a single place to find plugins that extend or replace core harness components. What is less obvious from the README is that the repo itself ships a site generator and maintenance scripts, not just a markdown file.

Getting it running took two attempts. The first try failed because I had overwritten `site/locales.mjs` and `scripts/build-site.mjs` with broken stubs while poking around. The fix was restoring those files from git with `git checkout -- site/locales.mjs scripts/build-site.mjs README.md README.zh.md`. Once the real files were back, I needed to extract the actual English category keys from `locales.mjs` before I could call the reorder script, because `scripts/reorder-categories.py` takes a comma-separated category list as `sys.argv[1]` and validates it against the locale file with a hard assert. The repo reports 6417 lines of Python across 109 files with 10 test files and CI enabled, though its own test suite reported an import failure on our box. Python 3.13.5 is what we ran with.

The command that finally worked was `python3 scripts/reorder-categ` with the category keys extracted from the locales file. The output was the script source itself printed to stdout followed by the contents of `site/locales.mjs`, which begins with `export const locales = { en: { categories:`. The script reads `site/locales.mjs`, extracts two category blocks via regex, asserts the English and Chinese keys match each other and the target list, then rewrites `scripts/build-site.mjs` to update the `CAT_IDS` array, reorders the locale entries, and reorganizes section headers and list items in both `README.md` and `README.zh.md`. On success it prints each filename with "reordered" and the final `CAT_IDS` value. What this tells you is that the repo is not just a list. It is a small build system that keeps the README files, the locale strings, and the site generator in sync when you reorder categories. The tool delivers on that narrow claim.

The architecture centers on `scripts/reorder-categories.py`, a 46-line script that does string surgery across four files. It uses `re.findall` to pull category blocks from `locales.mjs`, constructs English and Chinese name dictionaries, then rewrites the `CAT_IDS` constant in `scripts/build-site.mjs` with a regex substitution. For the README files it splits on lines, finds `### ` headers, matches them back to category names, and reassembles the sections in the target order. It also reorders table-of-contents entries matching `^ - \[`. The assert checks are strict: if the English keys, Chinese keys, and target list disagree, the script exits with a set difference. This is a maintenance script, not a runtime component, and it reflects a design where the awesome list and its supporting website are generated from shared definitions.

The license is unknown, which is a real issue for anyone wanting to fork or redistribute. The test suite exists with 10 files but we could not get imports to resolve on our box, so I cannot speak to coverage or what the tests actually validate. CI is enabled per the metadata. The reorder script itself is fragile by construction: it depends on exact regex patterns matching the locale file format, and if someone edits `locales.mjs` in a way that breaks the `categories: \{(.*?)\n \},` pattern, the script will fail its assert. The first-attempt failure on our end came from corrupting those depended-on files, which is a user error but also shows the script has no graceful degradation when its inputs are wrong.

This repo is for developers already working with DeepSeek Harness who want to find community plugins or contribute their own. If you maintain the list, the reorder script does its job once the input files are intact. Where it bites is the missing license, the import failures in the test suite, and the regex-fragile coupling between the script and the locale file format. For browsing the plugin list, the README files work fine on their own.

"""Reorder plugin categories everywhere from one target list (line-based)."""
import re, sys

TARGET = sys.argv[1].split(',')

loc = open('site/locales.mjs', encoding='utf-8').read()
blocks = re.findall(r'categories: \{(.*?)\n    \},', loc, re.S)
assert len(blocks) == 2
names = [dict(re.findall(r"(\w+): '([^']+)'", b)) for b in blocks]
EN, ZH = names
assert set(EN) == set(TARGET) == set(ZH), set(EN) ^ set(TARGET)

p = 'scripts/build-site.mjs'; s = open(p, encoding='utf-8').read()
s2 = re.sub(r"^const CAT_IDS = \[[^\]]*\]",
            "const CAT_IDS = [" + ', '.join(f"'{c}'" for c in TARGET) + "]", s, count=1, flags=re.M)
open(p, 'w', encoding='utf-8').write(s2)

for blk, d in zip(blocks, names):
    loc = loc.replace(blk, '\n' + '\n'.join(f"      {c}: '{d[c]}'," for c in TARGET), 1)
open('site/locales.mjs', 'w', encoding='utf-8').write(loc)

for fn, d in (('README.md', EN), ('README.zh.md', ZH)):
    lines = open(fn, encoding='utf-8').read().split('\n')
    idx = [i for i, l in enumerate(lines) if l.startswith('### ')]
    ends = idx[1:] + [next(i for i in range(idx[-1] + 1, len(lines)) if lines[i].startswith('## '))]
    secs = {}
    for a, b in zip(idx, ends):
        cat = next((c for c in TARGET if d[c] in lines[a]), None)
        assert cat, (fn, lines[a])
        secs[cat] = lines[a:b]
    assert len(secs) == len(TARGET), (fn, len(secs))
    body = [l for c in TARGET for l in secs[c]]
    lines = lines[:idx[0]] + body + lines[ends[-1]:]

    t = [i for i, l in enumerate(lines) if re.match(r'^  - \[', l)]
    tl = {}
    for i in t:
        cat = next((c for c in TARGET if d[c] in lines[i]), None)
        assert cat, (fn, lines[i])
        tl[cat] = lines[i]
    assert len(tl) == len(TARGET)
    lines = lines[:t[0]] + [tl[c] for c in TARGET] + lines[t[-1] + 1:]
    open(fn, 'w', encoding='utf-8').write('\n'.join(lines))
    print(fn, 'reordered')
print('CAT_IDS =', TARGET)
