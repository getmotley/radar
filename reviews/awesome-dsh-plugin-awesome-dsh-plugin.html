I cloned awesome-dsh-plugin today expecting a list and found something denser. The repo bills itself as a curated list of community plugins for DeepSeek Harness, the open source agent framework from DeepSeek where everything is a plugin: models, tools, sandboxes, session storage, UI, even the agent loop itself. Plugins install via `dsh plugin add` and declare a `dsh.bundle` manifest. So the problem this solves is discovery. There are 2058 entries spread across 21 categories as of my run, and a companion marketplace repo called dsh-market aggregates them. This is not a hand edited README. It is a build pipeline that generates the READMEs from structured data.

Getting it running took two attempts. There is no package.json in the repo, which is the first thing that bites you. The scripts import Node modules at runtime. Specifically `scripts/lib/entries.mjs`, which `scripts/generate-readme.mjs` pulls in, requires `js-yaml` at import time. With no package.json, there is nothing telling you to install it. The fix was `npm install js-yaml`, which dropped a local `node_modules` into the repo root. After that the Python and Node scripts cooperated. The test suite the repo ships reported import failed on the first attempt, consistent with the missing dependency. Ten test files exist in the metadata but the suite itself was not helpful here. The real validation came from running the scripts directly.

I ran `scripts/reorder-categories.py` as an idempotent demo, feeding it the same category order already in the file. The script reads `site/locales.mjs`, finds two `categories` blocks via regex, reads `CAT_IDS` from `scripts/lib/entries.mjs`, asserts the English and Chinese category sets match each other and the target, rewrites `CAT_IDS`, rewrites both locale blocks, then shells out to `node scripts/generate-readme.mjs`. My input was the existing order: ui, usage, theme, model, identity, session, memory, tools, browser, vision, voice, docs, skill, workflow, git, notify, dev, security, remote, market, fun. The output told me a lot. It printed "README.md: up to date (2058 entries)" and the same for the Chinese README. It flagged 6 entries awaiting translation, listing real repo URLs like domparent/OLEDCare and chenbin-dev/dsh-auth-everying. Then it confirmed both files were updated and printed the final CAT_IDS. The category order was unchanged because I passed the same order back in, which is exactly what idempotent means. The tool delivered: the pipeline ran end to end, the READMEs regenerated, and the translation gaps surfaced.

The architecture is a static site generator disguised as a list. Plugin entries live in `data/plugins/*.yml`. The build reads those YAML files, applies the category taxonomy from `CAT_IDS` in `scripts/lib/entries.mjs`, and emits both `README.md` and `README.zh.md` via `generate-readme.mjs`. Locals come from `site/locales.mjs`, which holds parallel English and Chinese category name maps. `reorder-categories.py` is a taxonomy reshaper: it rewrites the category order in three places at once and regenerates the READMEs so they stay consistent. The repo is 6644 lines across 2188 files, mostly Python and Shell, with 6411 lines of Python and 233 of Shell. CI is enabled. License is unknown, which is a real gap for a list you might fork or vendor. The READMEs are generated artifacts, and the script warns that editing them by hand gets undone on the next generate run. That warning is in the docstring of `reorder-categories.py` itself.

The rough edges are what you would expect from a repo that grew to 2058 entries. No package.json means the Node tooling has no declared dependencies, so you discover them by running and failing. The test suite exists but reported import failed on first run, which suggests the tests assume a setup that is not documented. The six untranslated entries are minor but show the bilingual pipeline is not fully caught up. The category sets are asserted to match across English, Chinese, and the target, which is a good guard against drift, and the assertion fired clean on my run. The code itself is tight: `reorder-categories.py` is 40 lines, uses regex to find and rewrite the two locale blocks, and shells out to Node for the README step. It is procedural and readable.

This is for someone building on or around DeepSeek Harness who wants to browse what exists, or a maintainer reshaping the taxonomy. It is not for someone who wants a polished package with a license and a clean install. Where it bites: no license, no package.json, tests that assume an undocumented setup, and generated READMEs you must not edit by hand. For browsing 2058 plugins it works. For vendoring into something else, read the source first and sort out the license yourself.
