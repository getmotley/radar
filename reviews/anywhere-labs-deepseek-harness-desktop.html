I cloned anywhere-labs/deepseek-harness-desktop to see what the 17,792 stars actually point at. The repo sells itself as a desktop experience for the DeepSeek Harness ecosystem, but the README is upfront about its current state: it is a compatibility entry point, not a standalone product document, and it explicitly defers to a `deepseek-harness/` submodule for upstream docs. In practice the repo is a TypeScript monorepo, 59,386 lines across 504 files, MIT licensed, with 93 test files and CI configured. The core deliverable is an Electron bootstrap layered over a Cordis host runtime, with a community market plugin for installing third-party packages from npm.

Getting it running took three attempts and never fully succeeded. The main blocker was a native dependency. `yarn install --immutable` fetched fine but failed at the link step because `koffi@npm:3.1.5` could not build, exit code 1, with the build log written to a temporary path. Koffi is a Node FFI module used for native interop, and it needs a working C toolchain and matching headers. On this box that step failed, which cascaded into the rest of the install being incomplete. The dev script did partially run despite the failed install: tsdown kicked off and built `dsh-community-market/client` successfully, producing `lib/client.js` at 142.65 kB, then moved on to `dsh-plugin-desktop` with a long list of entry points including `src/index.ts`, `src/module-resolution.ts`, `src/webserver.ts`, `src/profile.ts`, and several more. The build output was cut off before completion, so I cannot confirm the full dev script finished. The test suite was our fallback and reported exit 1 per the run metadata.

The real output confirms the partial nature. The community market client bundled cleanly in 41ms with rolldown v1.1.5 under tsdown v0.22.2, and the plugin desktop build started with a wide set of entries. But the koffi failure means any code path touching native calls through that module would break at runtime. The repo uses Yarn with immutable installs and corepack, so anyone trying to reproduce should have corepack available, a working yarn, and a system capable of compiling native Node addons before expecting the dev script to complete.

Looking at the source, the architecture is layered and deliberate. `dsh-plugin-desktop/src/main.ts` is the Electron bootstrap, 1180 lines, importing from `@deepseek-ai/dsh-app-boot`, `@deepseek-ai/dsh-cmdline`, and `@deepseek-ai/dsh-home-paths`. It wires up crash reporting via `crash-evidence.ts`, diagnostics export, lifecycle recording, install recovery through `DesktopInstallRecoveryStore`, and profile management with functions like `beginDesktopProfileStartup`, `assertDesktopProfileName`, `createDesktopWebProfile`, `listDesktopProfiles`, `selectDesktopProfile`, `deleteDesktopProfile`. The Cordis plugin in `dsh-plugin-desktop/src/index.ts` declares `inject = ['webServer', 'webRuntime']` and exposes route handlers for profile create, delete, select, rollback, market select, terminal open, diagnostics export, and settings. The community market in `dsh-community-market/src/index.ts` is more compact, 100 lines, and interesting for its security posture: it creates a restricted HTTP client with `syntheticProxyHostnames: ['registry.npmjs.org']` and an npm registry verifier, meaning package installation is pinned to the official registry and verified, not arbitrary. The client side in `dsh-plugin-desktop/src/client/index.ts` is 92 lines, wiring directory picker bridges, workspace folder drop handling, boot health reporting, and desktop settings UI sections.

Quality is mixed in the parts I could observe. The code is well organized with clear separation between host bootstrap, Cordis plugin registration, client renderer, and the market service. There is real engineering in the install recovery store, the fail-loud process handling, and the restricted HTTP client. The 93 test files and CI are good signals. The rough edge is practical: a single native dependency failing to build halts the whole install, and the README being a thin compatibility stub means anyone arriving cold has to dig into submodule docs to understand what DSH actually is.

The verdict: this is for developers already inside the DeepSeek Harness ecosystem who need a desktop shell and a vetted community market. It is not a drop-in app for outsiders. If your machine cannot build koffi, you are stuck before you start. Use it if you are building on DSH and can satisfy the native build requirements; avoid it if you want a turnkey DeepSeek desktop client, because the install path is still the product.
