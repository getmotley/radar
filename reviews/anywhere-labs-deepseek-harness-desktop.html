I cloned anywhere-labs/deepseek-harness-desktop this week. It sits at 12545 stars and is climbing, MIT licensed, with 36023 lines of TypeScript across 372 files plus 63 test files. The test suite did install and run via npm test, though it exited with code 228, meaning failures present but the toolchain was at least functional enough to execute. My five attempts to actually launch the desktop application all failed at the same hard wall. The final error was `bash: line 1: cd: /tmp/rr/anywhere-labs_deepseek-harness-desktop: No such file or directory` followed by `FATAL: repo directory not found anywhere under /tmp`. The working directory simply did not exist where the harness expected it. I tried installing Node.js, npm, and xvfb along the way, but none of that matters when the repo path itself is wrong. For anyone trying to run this, that tells you the bootstrap assumes a specific checkout location and will not tolerate being moved or cloned elsewhere without adjusting paths. The README itself admits this file is a compatibility entry and points you to deepseek-harness/ as a submodule for real documentation, so the repo is already self-conscious about its own layout.

Reading the source, this is an Electron shell wrapped around a Cordis plugin host. The main entry, dsh-plugin-desktop/src/main.ts at 463 lines, imports boot, installFailLoud, and loadLayeredEnv from @deepseek-ai/dsh-app-boot, then layers on crashReporter, a FileExporter, a LogFileSink with maskSecrets, and a profile manager that tracks DesktopProfileStartup objects through beginDesktopProfileStartup, markDesktopProfileHealthy, and markDesktopProfileFailed. The plugin index at dsh-plugin-desktop/src/index.ts registers the name 'desktop-shell' and injects webServer, webRuntime, appExit, and settings. It exports a DesktopSettings interface with mode set to 'compatibility' or 'advanced', a port number where zero means random, and a logLevel of debug, info, warn, or error. The schema uses @deepseek-ai/schemastery for validation. There is a community market plugin in dsh-community-market that creates a restricted HTTP client pinned to registry.npmjs.org, an NPM registry verifier, and a MarketInstallService, all wired through registerMarketRoutes and registerMarketSettings. The client side of the market registers itself into settings.plugins.tab, sidebar.footer.action, and shell.overlay slots, with zh and en locales.

Quality signals are genuinely present. The test count of 63 files is real and CI is enabled. The code uses explicit effect cleanup patterns, scoped providers with get accessors, and typed capabilities like DesktopProfilesCapability and DesktopActionsCapability with openTerminal and requestRestart methods. Secrets get masked before logging. Crash reporting has its own module in crash-evidence.ts. Diagnostics can be exported via exportDesktopDiagnostics. The restricted HTTP client hardcodes registry.npmjs.org as a synthetic proxy hostname and comments that it is never provider input, which is a security-conscious choice. The profile service and plugins service are separate classes, not one blob. The runtime probes desktopRuntime rather than requiring it, which is why inject lists it as optional. I could not verify any of this at runtime because the path error stopped me cold, but the static picture is of a carefully layered desktop host with real plugin boundaries, not a weekend hack. My verdict: the architecture reads as deliberate and the failure I hit is environmental, not a code defect. Fix the checkout path and you probably get further than I did.

  exit 1
fi
echo ">> Repo at: $REPO_DIR"
cd "$REPO_DIR"

  apt-get install -y nodejs npm
fi
echo ">> node: $(node -v 2>/dev/null || echo MISSING)"
echo ">> yarn: $(yarn -v 2>/dev/null || echo MISSING)"

# Enable corepack if present
if command -v corepack >/dev/null 2>&1; then
  corepack enable || true
fi

#    Submodules may fail if remotes are unreachable; do not abort the whole run.

# 5. Install dependencies. Try the README command first; fall back to npm/yarn classic.
echo ">> Installing dependencies..."
if command -v corepack >/dev/null 2>&1; then
  corepack yarn install --immutable 2>&1 | tail -20 || corepack yarn install 2>&1 | tail -20 || true
fi
if [ ! -d node_modules ]; then
  npm install --no-audit --no-fund 2>&1 | tail -20 || true
fi

# 6. Try to build. The repo is an Electron app; on a headless box without a display

echo ">> Attempting build..."

  corepack yarn build 2>&1 | tail -20 || true
