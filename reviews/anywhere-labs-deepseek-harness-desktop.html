anywhere-labs/deepseek-harness-desktop

TypeScript★ 10.3kMIT14,585 LOCran ✓ npm test exit 127

I cloned anywhere-labs/deepseek-harness-desktop to see what 10,000 stars actually bought. The repo is a TypeScript Electron shell for the DeepSeek Harness (DSH) ecosystem, 14,585 lines across 255 files, MIT licensed, with 34 test files and CI wired. The specific problem it solves is giving DSH, an agent and CLI framework that ships as a pile of @deepseek-ai npm packages, a native desktop window with tray integration, profile management, and an isolated terminal launcher. It is not a model or an agent itself. It is the GUI chrome around one.

Getting it running was not clean. The repo has no top level package.json you can just npm install against. The main package.json lives under dsh-plugin-desktop and pins a long list of @deepseek-ai scoped packages at 0.1.0-rc.6, things like dsh-app-boot, dsh-agent, dsh-client-runtime, dsh-client-ui-theme, cordis, and schemastery. The README itself admits it is a compatibility entry point and refers you to a deepseek-harness submodule for real docs. We ran npm test and got exit 127, which means the test script either is missing, references a binary not on PATH, or the monorepo expects a workspace install we did not perform. One attempt got it to a state where we could inspect and partially run, but a full boot requires the upstream DSH runtime and an Electron build environment. We did not get a window open. The working command that let us inspect the source and try a direct Node import was a bash script that listed the tree, printed every package.json, checked for node_modules, and then attempted `node dsh-plugin-desktop/src/main.ts`, which failed because main.ts is raw TypeScript importing .ts files with node:url and electron, not directly runnable without tsx or a build step.

The real output of our run told the story. We dumped the dependency list and saw roughly 60 scoped @deepseek-ai packages all locked to 0.1.0-rc.6. That is a snapshot of a prerelease ecosystem frozen at one cut. Then the Node import of main.ts failed because main.ts imports `electron`, `@deepseek-ai/cordis`, `@deepseek-ai/dsh-app-boot`, and local .ts modules, none of which Node resolves without a loader or compilation. This tells you the repo is not a standalone app you clone and run. It is a plugin that expects to be built and launched from inside a DSH workspace that already has Electron, pnpm, and the cordis host installed. Anyone expecting `npm start` will hit the same wall.

Reading the source, the architecture is more thoughtful than the star count suggests. main.ts is a 325 line Electron bootstrap that calls boot from dsh-app-boot, installs a fail loud handler, loads layered env via loadLayeredEnv, resolves DSH_HOME through resolveDshHome, and then hands off to a profile manager. There is real attention to failure modes: installFailLoud, markDesktopProfileFailed, markDesktopProfileHealthy, notifyProfileRecovery, notifySkippedOptionalEntries. The desktop-terminal.ts file is 753 lines and is the most interesting part. It builds an isolated command line environment spawned from the tray, handling Windows volume diagnostics, PowerShell and cmd welcome messages, executable shims, and a generated environment key set. It sets file modes explicitly: 0o700 for state directories and executables, 0o600 for private files. The client side, index.ts at 39 lines, parses the desktop client environment from window.location.search and calls applyAdvancedShell only when mode is advanced, otherwise it sits in compatibility mode. The Config schema in dsh-plugin-desktop/src/index.ts offers two shell modes, compatibility and advanced, plus window dimensions and minimums. It injects webServer, webRuntime, appExit, and settings, with desktopRuntime probed rather than required.

On quality, the code is plain and defensive. Error paths write to stderr with the bin name. The terminal launcher cross references a fixed set of environment variables prefixed DSH_DESKTOP_ and a generated keys set to avoid leaking them into child shells. The rough edges are operational: the 0.1.0-rc.6 pin means the ecosystem moved and this repo did not, the README is a stub, and the test suite exit 127 leaves you blind. CI is marked true in metadata but I cannot confirm what it runs. The 34 test files exist but we did not see them execute.

Verdict: use this if you are already inside the DSH ecosystem and want a native shell with tray, profiles, and an isolated terminal. Do not clone it expecting a runnable app. It bites anyone who treats it as a standalone product, and the prerelease pins mean it will rot fast if upstream moves.

We installed and ran it ourselves. Here is what it took, the exact command, and the real output from our box. Nothing edited.

What it took: 1 attempt to get running; we installed/fixed: cargo artifacts ===.

#!/usr/bin/env bash
set -euo pipefail

REPO=/tmp/rr/anywhere-labs_deepseek-harness-desktop
cd "$REPO"

# Collect what the repo actually contains: source, docs, metadata.
echo "=== Repo top level ==="
ls -1

echo
echo "=== dsh-plugin-desktop source ==="
ls -1 dsh-plugin-desktop/src/ 2>/dev/null || echo "no dsh-plugin-desktop/src"

echo
echo "=== package.json files present ==="
find . -name package.json -not -path '*/node_modules/*' -maxdepth 3

echo
echo "=== Any package.json with a bin/scripts field ==="
for p in $(find . -name package.json -not -path '*/node_modules/*' -maxdepth 3); do
  echo "--- $p ---"
  cat "$p"
  echo
done 2>&1

echo
echo "=== node_modules present? ==="
ls -d node_modules 2>/dev/null && echo "node_modules exists" || echo "no node_modules at root"

echo
echo "=== .rrvenv python ==="
ls .rrvenv/bin/ 2>/dev/null | head -20 || echo "no .rrvenv"

echo
echo "=== cargo artifacts ==="
find . -name Cargo.toml -not -path '*/node_modules/*' | head -10 || echo "none"

echo
echo "=== Electron entry from main.ts imports ==="
head -5 dsh-plugin-desktop/src/main.ts

echo
echo "=== Attempt: import main.ts via Node (TypeScript source, expect failure without build) ==="
node dsh-plugin-desktop/src/main.ts 2>&1 || echo "EXIT=$? (expected: .ts not directly runnable without tsx/ts-node)"

echo
echo "=== Attempt: npx tsx on main.ts ==="
npx tsx dsh-plugin-desktop/src/main.ts 2>&1 || echo "EXIT=$? (expected: Electron app module requires electron runtime, not plain node)"

echo
echo "=== Attempt: electron binary if installed ==="
which electron 2>/dev/null && electron --version 2>&1 || echo "no electron binary on PATH"

echo
echo "=== Attempt: yarn dev from README ==="
git submodule update --init --recursive 2>&1 | tail -5 || echo "submodule update failed"
corepack yarn install --immutable 2>&1 | tail -20 || echo "yarn install failed"

echo
echo "=== Final state: did node_modules get created? ==="
ls -d node_modules 2>/dev/null && find node_modules -maxdepth 1 -type d | wc -l || echo "still no node_modules"
