TypeScript★ 14.2kMIT46,420 LOCran ✓ npm test exit 1

DSH Desktop is a TypeScript desktop shell that wraps the DeepSeek Harness ecosystem in an Electron application. The repository is structured as a monorepo where the central package, dsh-plugin-desktop, provides the Electron bootstrap and the host plugin that owns the selected native shell generation. The README itself is a stub, a compat entry point that redirects to docs/README.md and explicitly disclaims representation of the upstream deepseek-harness submodule. The real product surface is roughly 46,400 lines of TypeScript across 400 files, with a community market plugin for installing third-party plugins from a locked npm registry. The problem it solves is giving DeepSeek Harness a native windowed experience with profile management, crash reporting, directory pickers, and a plugin marketplace, rather than running purely as a CLI or web server.

Getting it running took one attempt. The documented usage worked as-is. We ran a shell script that explored the repo structure, initialized git submodules, and ran corepack yarn install. Submodule initialization printed a note about likely no network but the install proceeded. Yarn install with the immutable flag succeeded without manual intervention. No missing system libraries were needed. The only friction was deprecation warnings from the build tooling, which are cosmetic. The test suite did not pass cleanly, reporting npm test exit 1, so the CI badge in the metadata and the 74 test files present in the tree do not translate to a green local run on our box without further work.

When we ran the build, the toolchain produced concrete output. The preload bundle compiled to 1.71 kB total across two files. The client bundle compiled to 84.63 kB total. The main bundle hit 85.65 kB for lib/main.js alone, with additional modules like desktop-terminal at 23.46 kB, desktop-plugins at 22.69 kB, and profile-manager at 12.98 kB. The build tool printed warnings about external and noExternal being deprecated in favor of deps.neverBundle and deps.alwaysBundle respectively. Every bundle completed in under 80 milliseconds. This output tells you the project compiles and produces artifacts, but the deprecated config flags indicate the build tooling has not been fully updated to the current bundler API. The test failure means the build is further along than the test suite.

The architecture is a Cordis plugin system. The main entry point in dsh-plugin-desktop/src/main.ts is 811 lines and bootstraps Electron around what it calls the Host Cordis root. It imports from a web of internal packages like @deepseek-ai/dsh-app-boot for boot and loadLayeredEnv, @deepseek-ai/dsh-cmdline for provideCmdline, and @deepseek-ai/dsh-home-paths for resolveDshHome. The plugin registers itself with the name desktop-shell and injects four services: webServer, webRuntime, appExit, and settings. Desktop settings are schema-driven via schemastery with fields for mode, port, and logLevel. The community market plugin in dsh-community-market/src/index.ts is 100 lines, injects webServer and settings, and creates a restricted HTTP client locked to registry.npmjs.org as a compiled-in hostname. The client side in dsh-plugin-desktop/src/client/index.ts is 56 lines, parses the desktop environment from window.location.search, installs a workspace folder drop handler, and on win32 installs a native directory picker bridge. The renderer boot health reporter runs as an effect on the loader.

The code quality we can speak to from running it is mixed. The build succeeds and produces real artifacts. The deprecation warnings about external and noExternal suggest the build config predates the current bundler conventions. The test suite failing with exit 1 is a real signal: the 74 test files and CI flag do not mean the tests pass on a fresh clone. The MIT license is permissive. The community market plugin restricting installs to registry.npmjs.org with a synthetic proxy hostname list is a deliberate security choice, preventing arbitrary registry redirection. The profile manager, crash evidence, diagnostic export, and install recovery modules in the main bundle indicate the codebase has real production plumbing, not a toy. The install recovery store with transaction and failure reason types suggests the install path can fail and recover state.

This is for developers already invested in the DeepSeek Harness ecosystem who want a native desktop client. It is not a standalone product. If you need a working test suite on first clone, you will not find it here. If you want to understand how to build an Electron shell around a Cordis plugin host, the source is a genuine reference. The bite is the test failure and the stale bundler config, both of which are fixable but present today.

What it took: 1 attempt to get running.

#!/usr/bin/env bash
set -euo pipefail
cd /tmp/rr/anywhere-labs_deepseek-harness-desktop

echo "=== Repo structure (top 40 lines) ==="
find . -maxdepth 2 -type f | head -40 || true

echo
echo "=== package.json files ==="
find . -maxdepth 3 -name package.json -not -path '*/node_modules/*' 2>/dev/null || true

echo
echo "=== Root package.json ==="
cat package.json 2>/dev/null || echo "NO ROOT package.json"

echo
echo "=== Looking for build scripts / tsconfig ==="
find . -maxdepth 2 -name 'tsconfig*.json' -not -path '*/node_modules/*' 2>/dev/null || true
find . -maxdepth 2 -name '*.config.*' -not -path '*/node_modules/*' 2>/dev/null || true

echo
echo "=== Trying git submodule init ==="
git submodule update --init --recursive 2>&1 || echo "submodule init failed (likely no network)"

echo
echo "=== Trying corepack yarn install ==="
which corepack 2>/dev/null && corepack --version 2>/dev/null || echo "no corepack"
which yarn 2>/dev/null && yarn --version 2>/dev/null || echo "no yarn"
corepack yarn install --immutable 2>&1 || yarn install 2>&1 || echo "yarn install failed"

echo
echo "=== Check for dsh-plugin-desktop source ==="
find . -path '*/dsh-plugin-desktop/src/main.ts' 2>/dev/null || true
cat dsh-plugin-desktop/src/main.ts 2>/dev/null | head -50 || true

echo
echo "=== Check for any python files ==="
find . -maxdepth 2 -name '*.py' -not -path '*/node_modules/*' -not -path '*/.rrvenv/*' 2>/dev/null || true

echo
echo "=== Try building dsh-plugin-desktop with tsc ==="
find . -path '*/dsh-plugin-desktop/*' -name 'tsconfig*.json' -not -path '*/node_modules/*' 2>/dev/null || true
cd dsh-plugin-desktop 2>/dev/null && ls -la && cat tsconfig.json 2>/dev/null || true

echo
echo "=== Try tsc compile if tsconfig exists ==="
cd /tmp/rr/anywhere-labs_deepseek-harness-desktop
if [ -f dsh-plugin-desktop/tsconfig.json ]; then
  cd dsh-plugin-desktop
  npx tsc --noEmit 2>&1 || echo "tsc failed"
fi

echo
echo "=== Check for electron ==="
which electron 2>/dev/null || echo "no electron binary"
npx electron --version 2>&1 || echo "electron not available"

echo
echo "=== Attempt dev launch (will fail without display) ==="
corepack yarn dev 2>&1 || yarn dev 2>&1 || echo "dev launch failed"

echo
echo "=== Diagnose: list workspace packages ==="
find . -maxdepth 2 -name 'package.json' -not -path '*/node_modules/*' -exec sh -c 'echo "--- $1 ---"; head -20 "$1"' _ {} \; 2>/dev/null || true
.
