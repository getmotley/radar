I cloned anywhere-labs/deepseek-harness-desktop today to see what 15,758 GitHub stars actually buy you. The README opens in Chinese and immediately tells you it is a compatibility entry point, not a standalone product document, and that the real docs live in a `deepseek-harness/` submodule. What you are getting is a TypeScript Electron desktop shell, 50,698 lines of TypeScript across 445 files, MIT licensed, built around the DeepSeek Harness (DSH) ecosystem. The problem it solves is giving DSH a native window with profile management, directory pickers, workspace folder drag-and-drop, and a community plugin market, rather than running everything through a bare browser tab.

Getting it on disk was straightforward. The package.json declares an engine constraint of Node `^22.19.0 || >=24.0.0`, which is the first thing that will bite if your box is on an older LTS. I ran the documented checkout and the install commands as-is, no manual dependency additions or system library installs were needed. It took one attempt. The repository splits into workspaces including `dsh-plugin-desktop` and `dsh-community-market`, and the build pipeline is layered: icon generation scripts, a clean step, `tsdown` for bundling, then two separate `tsc --emitDeclarationOnly` passes against `tsconfig.json` and `tsconfig.client.json`. The full `check` script chains build, typecheck, test, and four verify scripts covering runtime closure, CLI runtime, loader boot, and profile boot, which tells you the authors care about boot-time integrity, not just unit tests.

When I ran `npm test`, vitest exited with code 1. The test suite reports failure, which is the honest state of this clone on our box. Looking at the concrete output that landed, the package.json `files` array exposes `*.d.ts`, three README variants, and `THIRD_PARTY_NOTICES.md`, and the `dsh.client` block injects `@deepseek-ai/dsh-client-runtime` and `@deepseek-ai/dsh-client-ui-theme` with platform set to `web`. The `dsh.bundle.patch` points at `./cordis.patch.yml`, meaning the Cordis dependency framework is patched at bundle time rather than forked. So the tool installs and its metadata is coherent, but its own test suite does not pass green on a fresh clone, which is a flag for anyone wanting to build on top of it.

The architecture is a Cordis plugin tree, not a monolithic Electron app. `dsh-plugin-desktop/src/main.ts` is 769 lines of bootstrap that imports from `@deepseek-ai/dsh-app-boot` for `boot`, `installFailLoud`, `loadLayeredEnv`, and `resolveProfileDir`, then layers desktop-specific runtime installers via `installDesktopDshRuntime` and `installDesktopPnpmRuntime`. Crash reporting goes through `beginDesktopRun` and `startDesktopCrashReporting` from `crash-evidence.ts`, and secrets are scrubbed by `maskSecrets` before hitting `LogFileSink`. `src/index.ts` registers the `desktop-shell` plugin with `inject = ['webServer', 'webRuntime', 'appExit', 'settings']` and exposes a `DesktopSettings` schema with `mode`, `port`, and `logLevel` fields. `dsh-community-market/src/index.ts` is a separate 100-line plugin named `community-market` that builds a restricted HTTP client pinned to `registry.npmjs.org` as a compiled-in synthetic proxy hostname, then wires `MarketInstallService` with optional `desktopActions` and `desktopPlugins` capabilities injected only if present. The client side in `src/client/index.ts` is 59 lines that parse `window.location.search` for environment, start a renderer boot reporter, install workspace folder drop handling, and on `win32` route directory validation back through the main process via `requestDesktopDirectoryValidation`.

The code is more carefully structured than the star count and the failing tests would suggest together. Secret masking before logging, install-recovery transactions via `DesktopInstallRecoveryStore`, and a renderer boot health report path are not things a toy project ships. There are 82 test files and CI is enabled, though the suite fails on our run. The TypeScript is strict enough to warrant four separate typecheck configs. Rough edges: the README is a redirect stub, the test suite exits non-zero on a clean clone, and the Node version floor is high. This is for developers already inside the DSH ecosystem who need a native shell with profile and plugin management. If you are outside that ecosystem or need a green test run before trusting a desktop app, wait or prepare to debug vitest failures yourself.
