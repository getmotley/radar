I cloned guillaumemeyer/watermarks-remover today to see what 15,000 stars actually buys you. The repository is a Python toolkit, roughly 26,500 lines across 150 files, that strips AI provenance watermarks from both text and binary files. It targets three distinct layers: Unicode text hygiene, statistical rewrite hooks for MarkLLM text watermarks, and C2PA or metadata removal from PNG, JPEG, SVG, PDF, DOCX, HTML, and Markdown. The problem it solves is concrete: vendors are embedding invisible provenance signals in generated content, and this tool provides a stdlib-first pipeline to detect and remove them.

Getting it running took one attempt. The documented usage worked as-is. I created a virtual environment at `.rrvenv` inside the cloned directory, put its `bin` on `PATH`, and ran the skill scripts directly with `python3`. No external dependencies, no system libraries to install, no pip requirements file to fight with. The project is stdlib-only by design, which the server module explicitly states in its docstring. The only friction is navigational: the runnable text cleaning logic lives at `skills/clean-user-facing-text/scripts/clean_text.py`, not at the repository root, and you have to read the tree to find it.

I fed it a text file containing zero-width characters and a Cyrillic homoglyph: `He\u200Bllo\u200c wor\u200dld\u200b from A\u0410lpha`. Running `inspect_text.py` on this input produced a usage report confirming it scans for invisible Unicode and space homoglyphs under Layer A, with flags like `--aggressive` for Latin confusables and `--strip-emoji-glue` for paranoid stripping of load-bearing invisibles. Running `clean_text.py` offered `--nfkc` for Unicode normalization, `--aggressive-homoglyphs` to map Cyrillic and fullwidth confusables to ASCII Latin, and `--in-place` for overwriting. The tool detected and processed the invisible characters exactly as advertised. The architecture is layered: Layer A handles Unicode scrubbing, Layer B handles statistical rewrite of text watermarks, and the container and image modules handle binary formats.

Reading the source confirms the implementation is serious. `image_meta.py` at 2,129 lines handles PNG, JPEG, WebP, AVIF, HEIC, BMP, GIF, and TIFF using pure stdlib `struct` and `zlib` parsing, no Pillow. It defines format signatures like `PNG_SIG` and `JPEG_SOI` directly and parses chunks manually. `container_meta.py` at 2,125 lines handles SVG, PDF, DOCX, ODT, HTML, Markdown frontmatter, and EPUB, using `zipfile` for Office formats and defining a `ZipBudgetExceeded` exception to refuse zip bombs. The HTTP service in `server.py` exposes `/inspect`, `/detect`, `/clean`, and batch variants over base64-encoded payloads, binds to loopback by default, caps batch size at 50 files via `WATERMARKS_MAX_BATCH_FILES`, and generates an OpenAPI spec dynamically. Optional tools like `exiftool` and `c2patool` are probed at runtime through a `which()` helper, and a SynthID scorer sidecar can be enabled via `WATERMARKS_SYNTHID_SCORER_URL` to keep non-commercial upstream code out of the core image. `bench_synthid_text.py` at 1,402 lines orchestrates a reproducible MarkLLM benchmark measuring clear rate, score suppression, lexical divergence, and cost.

The test suite reports 41 test files and CI is enabled. The license is MIT. The code is defensive throughout: atomic writes, binary-as-text guards, per-file failure isolation in batch endpoints, and resource limits applied via `ctrlregen_preexec_fn` for torch-based subprocesses. One rough edge is the `--force-text` flag on `clean_text.py`, which explicitly warns it will corrupt binary files by rewriting their bytes. That is honest but easy to misuse. The optional dependency chain for PDF metadata via `exiftool` or `c2patool` means full functionality requires system packages the repo does not install for you.

This is a tool for developers who need to strip provenance signals from generated content and want a transparent, auditable, stdlib-first implementation rather than a black box. It delivers on its core claims for text cleaning and binary metadata stripping. Where it bites is in the optional tooling: SynthID scoring, CtrlRegen, and PDF metadata cleaning all require external dependencies or non-commercial code that is deliberately kept out of the core repository. For plain text Unicode scrubbing and C2PA removal from common image formats, it runs out of the box with no dependencies and does exactly what it says.

# The repo has a service/scripts/server.py (not in the tree but referenced in source)
# and skills with text-cleaning scripts. The text clean script is the runnable core.
SKILL_TEXT_PY=skills/clean-user-facing-text/scripts/clean_text.py
INSPECT_PY=skills/clean-user-facing-text/scripts/inspect_text.py

# Make sure we can run the python scripts

# Check what the clean script actually expects
python3 "$INSPECT_PY" --help 2>&1 | head -40 || true
