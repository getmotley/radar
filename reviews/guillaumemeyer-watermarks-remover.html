I cloned guillaumemeyer/watermarks-remover today, a Python project at 17,585 stars that strips AI provenance marks from files. It targets C2PA metadata, SynthID signals, Unicode text hygiene, and statistical rewrite hooks across PNG, JPEG, SVG, PDF, DOCX, HTML, and Markdown. The repo is 29,719 lines across 163 files under an MIT license, with 48 test files and CI configured. It took three attempts to get it running. The core issue was missing Pillow, numpy, and scipy. The README claims stdlib first, but image pixel processing requires these libraries. Running pip install pillow numpy scipy resolved the dependency gap. After that, the server started cleanly on port 8731, binding to loopback only by default and printing a stderr warning about no API key set.

I created a test PNG using Pillow, drawing a text string and a Unicode star character, and saved it to disk. I then started the HTTP service via python3 service/scripts/server.py and hit three endpoints. The GET /health endpoint returned {"ok": true, "version": "dev"}. The POST /inspect endpoint accepted a base64 encoded PNG and returned a JSON report. The report showed the format as png, has_c2pa as false, has_ai_metadata as false, findings as an empty list, and suspicious as false. It also noted that optional tools c2patool and exiftool were not available on my box. The POST /clean endpoint accepted the same base64 PNG and returned a cleaned file. The report listed the action as "no PNG metadata chunks removed (already clean or none matched)", with bytes_in at 1953 and bytes_out at 1953. The input and output sizes were identical because my test image had no AI metadata to remove. The tool correctly identified the absence of provenance marks and did not corrupt the file.

The architecture centers on service/scripts/server.py, a 1060 line stdlib HTTP service exposing /inspect, /detect, and /clean endpoints, each with single file and batch variants capped at 50 files per request. The server uses base64 encoding for file transfer and supports an optional bearer API key. The core logic lives in service/scripts/image_meta.py at 2172 lines, which handles raster formats including PNG, JPEG, WebP, AVIF, HEIC, BMP, GIF, and TIFF. It defines format signatures like PNG_SIG and JPEG_SOI and uses struct and zlib for parsing. The module includes a ctrlregen_preexec_fn function that sets higher RLIMIT_AS and RLIMIT_FSIZE caps for torch based pixel removal subprocesses, defaulting to 32 GB address space and 2 GB file size. The file service/scripts/container_meta.py at 2521 lines handles non raster containers like SVG, PDF, DOCX, ODT, HTML, and EPUB. It defines a ZipBudgetExceeded exception to catch zip bombs and handles multiple zip parse errors including BadZipFile, zlib.error, and RuntimeError. It imports AI_FRONTMATTER_KEYS as a frozenset containing generator, ai, openai, anthropic, gemini, synthid, and c2pa. The file service/scripts/bench_synthid_text.py at 1406 lines benchmarks MarkLLM text watermark removal, measuring clear rate, score suppression, and quality metrics like lexical divergence. The architecture is deliberately modular. server.py orchestrates, image_meta.py handles rasters, container_meta.py handles archives and markup, and bench_synthid_text.py handles text watermark benchmarks.

The codebase shows careful engineering. The ZipBudgetExceeded exception in container_meta.py is a specific defense against zip bombs. The batch endpoints in server.py isolate per file failures so one bad entry does not abort the rest. The optional tool probes in image_meta.py gracefully degrade when c2patool or exiftool are absent, as I observed in my run. The test suite has 48 files and the run reported tests passed. The CI badge is present. The optional SynthID scorer sidecar is isolated via an environment variable WATERMARKS_SYNTHID_SCORER_URL to keep the published core free of non commercial upstream code. One rough edge is the three attempts needed to install dependencies. The README says stdlib first but the pip install of pillow numpy scipy was required. The server stderr warning about binding to loopback is a good safety default but could confuse a new user expecting remote access.

This tool is for developers who need to audit or strip AI provenance metadata from files in a pipeline. It works as an HTTP service or CLI and handles a wide format range. It bites when you expect it to remove watermarks from clean files, as my test showed no changes. It also bites on dependencies since the stdlib first claim does not hold for image processing. The optional tools c2patool and exiftool add capability but are not installed by default. For a trusted network processing pipeline, this is a solid choice. For casual use, budget time for dependency setup and read the source for your specific format.
