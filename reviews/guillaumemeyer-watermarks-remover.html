watermarks-remover by Guillaume Meyer strips AI provenance marks from files. It targets three layers: Unicode text hygiene like homoglyphs and invisible characters, statistical rewrite hooks for token-sampling watermarks, and C2PA or metadata stripping from PNG, JPEG, SVG, PDF, DOCX, HTML, and Markdown. The repository has 12,235 stars and is rising, which suggests a real appetite for tools that remove machine-readable signals from AI-generated content. It is MIT licensed, written in Python with some Shell, and spans 17,045 lines across 113 files with 25 test files and CI enabled.

Getting it running took one attempt. The only dependency we had to add was Pillow, installed with pip. The test suite passed on its own. We ran the HTTP server in service/scripts/server.py, which binds to loopback only by default and uses stdlib HTTP handling with optional bearer token auth via WATERMARKS_SERVER_API_KEY. We hit three endpoints: GET /health returned ok true with version dev, POST /inspect on a 300x100 PNG returned a JSON report classifying it as image kind with format png, has_c2pa false, has_ai_metadata false, and empty findings, and POST /clean returned a 200 with a base64-encoded cleaned image. The server enforces a body cap of MAX_INPUT_BYTES plus half that to account for base64 inflation, and has a binary-as-text guard in common.py via looks_binary. Before finding the server path, we tried clean_text.py and inspect_text.py in skills/clean-user-facing-text/scripts on the same PNG. Both exited with code 2 and printed "refusing to treat /tmp/wm_input.png as text: it looks like a PNG image. This lightweight skill accepts text files only." That guard caught the mismatch immediately and refused to process it, which is the correct behavior for a text-only tool.

The test image we created had visible gray text reading "AI-MARK-12345" and "Summary: zH7k2pQ9xW" drawn on white. The inspect endpoint returned no findings because those are literal pixels, not metadata or C2PA assertions, and the tool does not OCR. The clean endpoint still returned a valid PNG, presumably with metadata stripped, though the base64 output was truncated in our capture so we could not confirm the exact diff. The report shows has_c2pa false and has_ai_metadata false, which is accurate for an image created from scratch with Pillow. The external tools c2patool and exiftool were both unavailable, which the report disclosed honestly. SynthID scoring was null.

The architecture is split across real modules. image_meta.py handles raster formats including PNG, JPEG, WebP, AVIF/HEIC via ISOBMFF, BMP, GIF, and both classic and BigTIFF. It defines format signatures like PNG_SIG and JPEG_SOI, and has a ctrlregen_preexec_fn that raises RLIMIT_AS to 32 gigabytes for torch-based subprocesses. container_meta.py covers SVG, PDF, DOCX, ODT, HTML, Markdown frontmatter, and EPUB. It imports the raster inspectors and strippers from image_meta and defines AI_FRONTMATTER_KEYS as a frozenset with entries like generator, claude, anthropic, openai, gemini, synthid, and c2pa. It also drops SVG metadata tags including xmpmeta and RDF. rewrite_text.py is the statistical watermark layer with three backends: print-prompt for CI-safe no-model operation, ollama for local inference, and openai-compatible for remote endpoints. It refuses redirects and denies non-loopback endpoints unless WATERMARKS_REWRITE_ALLOW_REMOTE is set.

The code is defensive in ways you notice. common.py exports guard_binary, safe_write_bytes, safe_write_text, subprocess_preexec_fn, and which, suggesting careful subprocess handling. The server caps input size, checks for binary content in text paths, and writes atomically. The rewrite hook never accepts API keys on argv, only environment variables. These are the choices of someone who thought about untrusted input. The 25 test files and CI badge mean the suite is not decorative. The rough edge we hit was discovering which entry point to use. The skills directory has lightweight text-only scripts that refuse images, while the real pipeline lives in service/scripts/server.py. A new user could waste time on the wrong entry point. Also, the PDF path prefers external exiftool or c2patool when present, so on a stock machine without those installed you get best-effort stdlib handling only.

This tool is for developers who need to strip C2PA assertions, AI metadata, and Unicode watermarks from files they own. It is not for removing visible watermarks from images you did not generate. It will not defeat statistical watermarks without a configured rewrite backend and a model. The core is stdlib-first, which keeps it portable, but optional features like SynthID scoring and CtrlRegen require external sidecars or torch. Use it as a library or HTTP service on a trusted network, put it behind a reverse proxy if exposed, and do not expect it to remove pixel-level marks.
