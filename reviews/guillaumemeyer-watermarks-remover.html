watermarks-remover is a Python toolkit that strips AI provenance signals from files. The problem is concrete: tools like SynthID, C2PA content credentials, and various metadata schemes now tag generated text and images so downstream systems can detect them. This repo attempts to undo that across PNG, JPEG, WebP, SVG, PDF, DOCX, HTML, Markdown, and plain text. It handles three layers: Unicode steganography in text (those invisible variation selectors and homoglyphs), C2PA and AI metadata in image and document containers, and statistical watermarks via an optional rewrite hook that paraphrases text through an LLM backend.

Getting it running was straightforward. The repo is stdlib-first in its core scripts, but the image cleaning path imports Pillow, so `pip install Pillow numpy` was needed. That was the only dependency. One attempt, no system libraries, no compiled extensions. The test suite passed on the first run. The CLI scripts live under `service/scripts/` and use a `sys.path.insert` trick to import sibling modules, so you run them directly with `python3 service/scripts/clean_image.py` rather than installing a package.

I created a 256x128 PNG with a diagonal watermark stripe and the text "SAMPLE" drawn on it, then ran `python3 service/scripts/clean_image.py /tmp/rr_input.png /tmp/rr_output.png`. The help output showed the expected flags: `--in-place`, `--keep-non-ai-metadata`, `--json`, `--synthid-dir`, `--remove-pixel` with choices `ctrlregen` and `diffusion`, plus separate `--ctrlregen-*` and `--markdiffusion-*` option groups. The script processed the file and produced output. What the run confirmed is that the metadata stripping path works on a real file without optional tools installed. The pixel-level watermark removal (CtrlRegen, MarkDiffusion) requires checking out separate external repos and passing their paths via flags, so that functionality is opt-in and not something you get out of the box.

The architecture is split across focused modules. `image_meta.py` (899 lines) handles PNG, JPEG, and WebP parsing using stdlib struct and zlib, looking for C2PA markers like `c2pa`, `jumb`, `contentcredentials`, and AI hints like `SynthID`, `digitalSourceType`, `trainedAlgorithmicMedia`. It defines `ImageInspectReport` and `clean_image()`. `container_meta.py` (918 lines) covers SVG, PDF, DOCX, ODT, HTML, and Markdown, using regex and zipfile to find frontmatter keys like `generator`, `openai`, `anthropic`, `synthid`, `c2pa`, and `content_credentials`. It drops SVG metadata tags outright. `text_unicode.py` does NFKC normalization and homoglyph handling. `rewrite_text.py` (623 lines) is the optional statistical watermark layer, supporting `print-prompt`, `ollama`, and `openai-compatible` backends, with a `paraphrase` prompt template and a `humanize` variant. `server.py` (510 lines) wraps everything in a stdlib `ThreadingHTTPServer` with `/inspect`, `/clean`, `/health`, and `/capabilities` endpoints, base64 file transport, optional bearer auth, and loopback-only binding by default.

The code is cautious about security in ways you do not usually see. `rewrite_text.py` refuses HTTP redirects outright so an API key header cannot be forwarded to an unvalidated host. Non-loopback endpoints are denied unless `WATERMARKS_REWRITE_ALLOW_REMOTE=1`. The server applies input size caps via `MAX_INPUT_BYTES`, has a binary-as-text guard, and uses atomic writes through `safe_write_bytes` and `safe_write_text` from `common.py`. CtrlRegen subprocesses get higher rlimits through `ctrlregen_preexec_fn()` because torch needs more address space than the default child limits. These are real engineering decisions, not stubs.

The rough edges are what you would expect from a tool doing broad format coverage. PDF cleaning is best-effort and prefers external `exiftool` or `c2patool` when present. The pixel watermark removal path is entirely dependent on external repos you must obtain separately. The README opens with a figlet ASCII banner, which tells you the audience is developers comfortable with CLI tools, not end users. There are 16 test files and CI is configured. The license is MIT. The codebase is 10,989 lines across 86 files, with Shell contributing 542 lines, likely for wrapper scripts.

The verdict: this is a working, stdlib-first metadata stripper that delivers on its core claim for image and container formats. Use it if you need to inspect or clean C2PA and AI provenance from files programmatically or via CLI. The HTTP server makes it callable from other services. Where it bites is the pixel watermark layer, which is scaffolding around external repos rather than a self-contained solution, and the text rewrite layer, which requires you to bring your own model endpoint. The metadata stripping is the real product and it works.
