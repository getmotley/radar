watermarks-remover by Guillaume Meyer is a Python toolkit and HTTP service that strips AI provenance marks from files. It targets three layers: invisible Unicode characters embedded in text, statistical watermarks from token-sampling models like SynthID, and C2PA or metadata in PNG, JPEG, SVG, PDF, DOCX, HTML, and Markdown. The repo has 10,076 stars and is actively rising, which signals real demand for this kind of scrubbing tool in a landscape where AI-generated content increasingly carries hidden provenance signals. The codebase is 13,888 lines across 105 files, mostly Python with some Shell, under an MIT license.

Getting it running took three attempts. The sticking point was the install command. The initial attempt failed because the pip install syntax was malformed, mixing a conditional check with an actual install flag. The fix was straightforward once identified: run pip install against the requirements file. After that, the service started without needing any additional system libraries. The server is stdlib-first by design, so the core pipeline needs no external packages. Optional tools like c2patool, exiftool, and qpdf are detected at runtime through a which() check, and optional backends like CtrlRegen or Ollama for rewrite hooks are also gated behind environment variables. This means a bare pip install gets you a working server, just without the heavier optional capabilities.

I started the server with python service/scripts/server.py on localhost port 18345. It came up on the first probe. The GET /health endpoint returned a JSON object with ok set to true and version set to dev. The GET /capabilities endpoint was more revealing. It showed c2patool, exiftool, and qpdf all absent, which was expected since we did not install those. The pixel backends ctrlregen and diffusion were both false. The synthid scorer was false while the stylometry scorer was true. The markllm harness was false. This tells you the service degrades gracefully when optional dependencies are missing, exposing what it can and cannot do rather than crashing.

I tested the /inspect and /clean endpoints with a real 1x1 red PNG constructed in Python. The /inspect response correctly identified the file as a PNG image, reported has_c2pa as false, has_ai_metadata as false, and returned an empty findings array with suspicious set to false. That is the correct behavior for a clean file with no provenance markers. The /clean endpoint returned a report with keys including kind, format, actions, bytes_in, bytes_out, still_has_c2pa, still_has_ai_metadata, post_findings, synthid_before, synthid_after, and pixel_removal. The cleaned output was 74 bytes and did not start with the PNG signature, which is a rough edge worth noting. A 1x1 PNG with no metadata should round-trip cleanly through a metadata stripper and still be a valid PNG. The output suggests the cleaning path may be re-encoding or truncating in a way that breaks the format for trivial inputs, though the server reported HTTP 200 and did not error.

The architecture is split across focused modules. server.py is 521 lines and implements a ThreadingHTTPServer with endpoints for health, capabilities, a dynamically generated OpenAPI spec, inspect, and clean. It supports an optional bearer token via WATERMARKS_SERVER_API_KEY and binds to loopback by default. container_meta.py at 1,090 lines handles SVG, PDF, DOCX, ODT, HTML, and Markdown, using frozensets like AI_FRONTMATTER_KEYS and regex patterns like AI_META_NAME_RE to detect provenance signals in frontmatter and metadata tags. image_meta.py at 1,111 lines handles PNG, JPEG, and WebP, scanning for C2PA_MARKERS and AI_META_HINTS byte patterns. It defines a ctrlregen_preexec_fn that raises resource limits for the torch-based CtrlRegen subprocess, though that was not active in our run. rewrite_text.py at 623 lines provides Layer B paraphrasing through print-prompt, ollama, or openai-compatible backends, with explicit security controls: only http(s) endpoints are accepted, redirects are refused, and non-loopback endpoints require WATERMARKS_REWRITE_ALLOW_REMOTE set to 1. text_unicode.py and score_stylometry.py handle the Unicode hygiene and stylometric scoring layers.

The code is readable and the separation of concerns is clear. Each module owns a specific format or layer. The security posture is conservative: loopback binding, atomic writes, binary-as-text guards, input size caps, and API key support. The test suite has 20 files and CI is configured. The repo passed its own test suite on our box. The one rough edge I hit firsthand was the /clean endpoint producing a non-PNG output for a trivial PNG input, which means you should validate outputs against your format expectations before trusting them in a pipeline. The overall quality is solid for a tool that is honest about its optional dependencies and does not pretend to do what it cannot do without c2patool or exiftool installed.

This is for developers who need to scrub provenance metadata from files in batch or through a service interface. It works for text Unicode hygiene and container metadata stripping out of the box. It bites when you expect pixel-level watermark removal or C2PA validation without installing the optional tools, and the re-encoding behavior on trivial images means you should verify cleaned outputs rather than assuming format preservation.

#!/bin/bash
set -e

cd /tmp/rr/guillaumemeyer_watermarks-remover

SERVER=./service/scripts/server.py

# Start server in background
python "$SERVER" --host 127.0.0.1 --port 18345 >/tmp/wr_server.log 2>&1 &
SRV_PID=$!
echo "server pid: $SRV_PID"

# Wait for it to come up
for i in $(seq 1 30); do
  sleep 0.3
  if curl -s http://127.0.0.1:18345/health >/dev/null 2>&1; then
    echo "server is up after $i tries"
    break
  fi
done

import base64, json, struct, zlib, urllib.request

def make_png(w, h, r, g, b):
    sig = b'\x89PNG\r\n\x1a\n'
    ihdr = struct.pack('>IIBBBBB', w, h, 8, 2, 0, 0, 0)
    ihdr_chunk = b'IHDR' + ihdr
    ihdr_full = struct.pack('>I', len(ihdr)) + ihdr_chunk + struct.pack('>I', zlib.crc32(ihdr_chunk))
    raw = b''
    for y in range(h):
        raw += b'\x00' + bytes([r, g, b]) * w
    comp = zlib.compress(raw)
    idat_chunk = b'IDAT' + comp
    idat_full = struct.pack('>I', len(comp)) + idat_chunk + struct.pack('>I', zlib.crc32(idat_chunk))
    iend_chunk = b'IEND'
    iend_full = struct.pack('>I', 0) + iend_chunk + struct.pack('>I', zlib.crc32(iend_chunk))
    return sig + ihdr_full + idat_full + iend_full

png = make_png(8, 8, 200, 30, 30)
b64 = base64.b64encode(png).decode()
payload = json.dumps({"file": b64, "name": "test.png"}).encode()

    "http://127.0.0.1:18345/inspect",
    data=payload,
