watermarks-remover is a Python project by guillaumemeyer with 8678 GitHub stars and climbing. It claims to strip AI provenance marks across a wide set of formats: PNG, JPEG, SVG, PDF, DOCX, HTML, and Markdown. The description mentions Unicode text hygiene, statistical rewrite hooks, and C2PA metadata removal. The repo is MIT licensed, contains 10989 lines across 86 files with 10447 lines of Python and 542 lines of Shell, ships 16 test files, and has CI configured.

I installed it with pip install -r requirements-dev.txt plus pytest, and the full test suite passed. Then I tried actually running the tool against a plain text file containing a sentence about AI generated content detection. The demo script attempted to call service/scripts/detect_text_watermark.py and service/scripts/clean_text.py. Every invocation failed with "python: can't open file '/tmp/service/scripts/detect_text_watermark.py': [Errno 2] No such file or directory" and the same for clean_text.py. Import checks for the service module and common module both failed with ModuleNotFoundError. The script cd'd to /tmp and never found the scripts because the relative paths assumed a working directory the demo did not establish. Nothing ran.

The signals are mixed. 10989 lines across 86 files with 16 test files, CI, and an MIT license suggest a real project, not a weekend throwaway. Tests passing confirms the codebase imports and runs under pytest. But the demo script could not find its own entry points, which means the documented path to actually using the tool is broken or the instructions assume setup steps that are not stated. That gap between passing tests and a runnable CLI is a real problem for anyone trying this cold.

I would not rely on this yet if you need a working command line tool today. The test suite passes, so the internals likely function, but the entry point documentation or packaging does not hold up. Clone it if you want to read the source or contribute fixes. Wait if you just want to run it.
