Praxist is an autonomous research system for measurable, computer-executable research. The README pitches it as a personal R&D team. The actual source confirms a multi-agent architecture built around a research loop with structured memory. The problem it targets is research work that produces machine-checkable findings rather than prose. The CLI package at praxist/cli/__init__.py exposes subcommands including setup, start, stop, status, resume, takeover, resolve, doctor, docs, examples, configure_llm, install_skills, product_usage, uninstall, and user_agreement. A dispatcher routes argv to handlers and returns exit 0 with top-level help when no subcommand is given, exit 2 on unknown verbs. The docstring notes compatibility with a lower-level python -m praxist.run entry point until a v1.0 window.

The implementation is layered. The finding graph MVP at praxist/plugins/graph_maintainers/finding_graph_mvp/cli.py offers five modes: backfill, health, daemon, viz, wipe. Backfill runs a rule engine over SQLite findings and upserts edges idempotently via a UNIQUE(src, dst, type) constraint. Health writes graph_health.json. Daemon starts a FindingGraphMaintainer in shadow mode. Viz renders a self-contained vis-network HTML page. Wipe deletes edges only. Memory is handled by append-only YAML ledgers under praxist/plugins/workflow_stages/research_loop/backend/research_memory/ledgers/. There are ten ledger types: Claim, Hypothesis, Mechanism, CoverageMatrix, NegativeEvidence, RetiredClaim, Dissent, FrontierDelta, and RoleROI. The usage collector at praxist/product_usage/app.py is a FastAPI app with a /healthz endpoint and a /v1/events ingestion route, backed by PostgresEventStore with a configurable max table byte limit and a fixed request body cap. Health checks deliberately suppress database exception details. The collector takes an enabled callable so ingestion can be gated externally.

Code quality is readable from what I can see. Modules carry focused docstrings with design references, type hints are consistent, and error handling is deliberate. The health endpoint catches broadly but returns a 503 without leaking internals, and the finding graph CLI validates run_dir existence before proceeding. One gap is the arXiv badge pointing to 2608.25955, which is not a valid arXiv identifier given the format, though I cannot say whether the paper is real. The test surface of 165 files with CI on is a good signal for a repo this size.

This is for teams that want an autonomous research harness with structured, checkable artifacts rather than a chatbot. The code is organized, the plugin system is real, and the ledgers are a thoughtful memory design. I cannot speak to runtime behavior because I did not run it. For developers evaluating it, the static picture is strong but the toolchain gap means you need GPU or ML weight access to exercise it yourself.
